# 第 0 节：并行文件边界与共享构建/编辑器锁规程

> 用法：把本节复制到任意 Unreal Engine 项目的实现指南中，替换尖括号占位符。不要把项目专属名称、私人路径或未确认的行为决策留在模板中。

## 0.1 适用范围与基线

- 项目标识：`<project-id>`
- 基线分支与 commit：`<base-branch>` / `<base-commit>`
- 共享锁根目录：`<shared-lock-dir>`
- 本节覆盖：并行 Worker 的文件边界、拓扑波次、UBT/UE Editor/UE MCP 宿主互斥和排队唤醒。
- 本节不覆盖：具体业务语义、资产内容、类接口、地图布置和项目专属验收标准；这些内容必须写在本指南其他章节。

开工前，Worker 必须确认当前分支、基线 commit 和工作区状态与上述记录一致。若不一致，先报告，不自行清理或切换。

## 0.2 Worker 切片与拓扑波次

| Worker | 只读范围 | 独占写入范围 | 验证夹具/方式 | 依赖波次 | 是否需要宿主锁 |
|---|---|---|---|---|---|
| `<worker-a>` | `<read-set-a>` | `Source/<Project>/<ModuleA>/` | `<fixture-a>` | `0` | `<yes/no>` |
| `<worker-b>` | `<read-set-b>` | `Content/<DomainA>/` | `<fixture-b>` | `1` | `<yes/no>` |
| `<worker-c>` | `<read-set-c>` | `<bridge-files>` | `<integration-check>` | `2` | `yes` |

并行拆分只有在以下条件全部成立时才有效：

1. 本指南已经定死每个切片的边界语义、状态归属和失败行为。
2. 各切片可以用程序化夹具、独立子模块、纯 C++ 测试或离线检查独立验证。
3. 源码文件无重叠；`<Module>.Build.cs`、`.uproject`、插件描述文件、`Config/*.ini` 和其他公共生成清单由单一 Worker/波次写入。
4. `.uasset`、`.umap` 和其他 UE 二进制资产的写入集合零重叠；每个文件只有一个明确写入者。

若公共文件需要多个切片配合，按以下顺序安排：

`前置骨架提交 → 独立实现波次 → 收口桥接提交`

不要把公共文件冲突留给 Git 合并，也不要让两个 Worker 同时保存同一资产。

## 0.3 共享锁定义

同一项目只使用以下锁目录：

`<shared-lock-dir>/<project-id>-build.lock`

锁目录内必须存在 `owner.txt`，首字段是当前会话 ID，记录格式为：

`<session-id> <iso-timestamp> <purpose>`

该锁互斥保护：

- UnrealBuildTool 编译；
- `UnrealEditor-Cmd` 无头测试；
- `UnrealEditor` 实例及其固定端口 MCP 服务；
- 会写入 `.uasset`、`.umap` 或其他 UE 二进制资产的编辑器导入/保存操作。

持锁期间禁止 Live Coding。脚本准备、代码阅读、离线资产解析和不启动 UE 宿主的测试准备属于锁外工作。

## 0.4 获取锁与有限排队

Worker 在启动或操作上述宿主前使用原子目录创建申请锁：

1. 创建成功后写入 `owner.txt`，确认首字段为自己的 `<session-id>`。
2. 目录已存在时先读 `owner.txt`，精确比较首字段；相同表示自己已持有，不得自锁阻塞。
3. 首字段不同、文件缺失或格式非法时视为冲突/损坏状态，记录可见信息，不覆盖、不修复、不删除。
4. 按 `<retry-interval>` 重试最多 `<retry-count>` 次。示例：`20s × 2`。
5. 达到上限仍冲突时，向 Orchestrator 发送排队/需要输入报告，列出锁路径、owner、已完成锁外工作和待执行锁内操作，然后挂起当前回合。禁止无限 sleep 轮询。

被唤醒后必须重新执行原子获取，不能复用此前观察到的空闲结果。

## 0.5 释放锁与孤儿锁

持锁 Worker 在 `finally` 或等价清理路径中按以下顺序收尾：

1. 退出自己启动的 `UnrealEditor*`、`UnrealBuildTool` 和 MCP 进程。
2. 确认这些进程已经退出，并重新读取 `owner.txt`。
3. 只有首字段仍为自己的 `<session-id>` 时，才删除锁目录。
4. 进程未退出、owner 不匹配或删除失败时，报告具体错误并保留现场。

Orchestrator 不得代删活跃 Worker 的锁。仅当会话已终止、锁仍存在、owner 不再活跃且确认没有对应 UE/UBT 残留进程时，才可以清理孤儿锁，并把核验结果通知排队 Worker。

## 0.6 锁内阶段与失败语义

持锁期间一次完成本 Worker 已准备好的构建、无头测试、编辑器/MCP 操作和必要资产保存。若构建、测试、连接、资产映射或保存失败，按本项目错误规范报告对象与原因并停止受影响阶段；不得改用默认资源、占位配置、替代流程、自动修正输入或吞掉异常。

## 0.7 收口验收

- [ ] 每个 Worker 只修改表格中的独占写入范围。
- [ ] 公共文件由指定 Worker/波次修改，二进制资产没有重叠写入。
- [ ] 每个并行切片都有独立验证证据。
- [ ] UBT、`UnrealEditor-Cmd`、`UnrealEditor` 和固定端口 MCP 操作遵守同一把锁。
- [ ] 冲突 Worker 在有限重试后排队，没有无限轮询。
- [ ] 持锁 Worker 退出自己启动的进程后才释放锁；Orchestrator 未删除活跃锁。
- [ ] 收口提交只包含本指南允许的文件和生成物。
