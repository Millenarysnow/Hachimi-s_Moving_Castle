# Unreal Engine 并行编排与独占宿主锁

本技能用于把一个 Unreal Engine 实现指南拆成可以安全并行执行的 Worker 拓扑，并在单机上协调 UnrealBuildTool（UBT）、无头编辑器测试、带 MCP 端口的编辑器实例和二进制资产。它只规定协作边界与宿主资源的生命周期，不替代具体项目的实现指南、引擎版本约定或验收标准。

## 何时加载

出现以下任一条件时加载本技能：

- 需要将 UE 任务派发给多个 Worker 并行实现或验证。
- 需要为任务安排前置骨架、并行实现、跨模块收口等拓扑波次。
- 需要在同一台机器上协调 UBT、`UnrealEditor-Cmd`、`UnrealEditor` 或 UE MCP 服务的独占使用。
- 需要定义共享构建/编辑器锁、排队、唤醒或孤儿锁清理规程。

若任务只修改普通文本且不触碰 UE 工具、公共配置或二进制资产，可以不加载本技能。

## 核心原则

1. **实现指南是唯一真相源。** Worker 只能实现指南已经定死的行为；并行编排不能补充未确认的业务语义。缺少会影响验收的边界决策时，先回报 Orchestrator，不用默认值、静默跳过或自动修正填补。
2. **先证明可并行，再创建 Worker。** 一个切片必须同时满足：边界语义已经定死；能用程序化夹具、独立子模块或明确的离线检查独立验证；源码、公共配置和资产文件与其他切片没有写入重叠。
3. **二进制资产绝不重叠。** `.uasset`、`.umap` 以及由 UE 生成并被提交的其他二进制资产只能归一个 Worker 或一个拓扑波次写入。Git 无法可靠合并这些文件，任何重叠都视为不可并行。
4. **宿主工具按项目级互斥。** UBT、`UnrealEditor-Cmd`、`UnrealEditor`（含固定端口的 MCP 服务）共享同一把锁；持锁期间禁止 Live Coding，避免模块和编辑器状态互相污染。
5. **锁由持有者闭环管理。** 只有成功核验自己会话 ID 的持有者可以释放锁。Orchestrator 不代删活跃 Worker 的锁，只能在会话已经终止且确认没有残留 UE/UBT 进程后清理孤儿锁。

## 拓扑波次与文件边界

### 拆分前检查

Orchestrator 在派发前建立一张切片表，至少包含 Worker、输入、写入路径、验证方式、依赖波次和是否需要宿主锁。检查以下内容：

- 语义边界：每个 Worker 的完成条件、失败行为、目标和状态归属均已在实现指南中明确。
- 依赖方向：只读依赖可以跨 Worker 共享；写入依赖必须排入后续波次，或先提交一个双方都认可的骨架。
- 公共文件：`*.Build.cs`、`.uproject`、插件描述文件、`Config/*.ini`、共享注册表、生成清单等只能由一个 Worker 在一个波次中修改。需要多个切片改动时，拆成“前置骨架提交 → 并行实现 → 收口桥接”。
- 二进制文件：为每个 `.uasset`、`.umap` 和其他 UE 二进制文件登记唯一写入者；不确定归属时停止拆分并报告。
- 验证夹具：每个并行切片必须有不会修改其他切片输出的测试夹具、纯 C++ 单元测试、离线解析或明确的静态检查。

### 推荐波次

- **波次 0：前置骨架。** 由单个 Worker 建立公共接口、目录、模块边界或最小可编译骨架，提交后才允许依赖它的 Worker 开始。
- **波次 1：独立实现。** 并行 Worker 只修改各自的源码目录、独立配置片段或独占资产集合，并使用各自的夹具验证。
- **波次 2：收口桥接。** 单个 Worker 修改公共注册、模块依赖、关卡引用或其他跨切片文件，持锁完成编译、编辑器测试和集成验证。

如果两个切片都必须写同一个公共文件，不能通过工作树隔离解决，必须改为串行波次或增加前置骨架/收口桥接。不要把冲突留给 Git 合并。

### 锁外与锁内工作

以下工作默认可以并行且不申请宿主锁：阅读代码、编写 C++、离线解析外部资产、准备 Python/MCP 脚本、生成不写入 UE 资产的测试数据。以下工作必须在锁内串行：UBT 构建、`UnrealEditor-Cmd` 无头测试、启动或操作 `UnrealEditor`、连接固定端口 MCP、保存或导入 UE 二进制资产。建议先攒齐锁外改动，再一次持锁完成构建与验证。

## 共享宿主锁

### 锁的格式与互斥范围

同一个项目在宿主共享目录约定唯一锁目录：

`<shared-lock-dir>/<project-id>-build.lock`

锁目录内必须有 `owner.txt`，首字段是当前持有会话的唯一 ID；推荐记录格式为：

`<session-id> <iso-timestamp> <purpose>`

创建锁必须使用原子目录创建操作。目录创建成功才算持有；发现目录已存在时，先读取 `owner.txt` 再决定是自锁还是他人锁。锁覆盖 UBT、`UnrealEditor-Cmd`、`UnrealEditor` 进程和固定端口 MCP 服务；Live Coding 不属于可替代的并行路径，持锁期间不得启用。

### 获取快路径

1. Worker 在需要启动 UE/UBT 宿主之前尝试原子创建锁目录并写入 `owner.txt`。
2. 若锁已存在，读取首字段并与自己的会话 ID 精确比较。首字段相同表示这是自己持有的锁，可以继续使用；不得把自锁当成冲突而阻塞自己。
3. 若首字段不同或 `owner.txt` 缺失、格式非法，按他人占用或损坏锁处理：记录锁路径和可见的 owner 信息，不能覆盖、修复或删除该锁。
4. 锁冲突只允许有限等待，例如间隔约 20 秒重试最多 2 次。达到上限仍冲突时，立即向 Orchestrator 发送排队/需要输入报告并挂起当前回合，禁止无限 `sleep` 轮询浪费上下文。

锁外的编译命令准备、参数检查和脚本生成不应提前创建锁；只有即将启动或操作宿主时才申请。

### 释放与异常

- 持锁 Worker 必须在 `finally` 或等价的清理路径中先退出自己拉起的 `UnrealEditor*`、`UnrealBuildTool` 和 MCP 进程，再重新读取 `owner.txt`，确认首字段仍是自己的会话 ID，最后删除锁目录。
- 任何进程未退出、锁所有权不再匹配或清理过程报错，都要报告明确错误并保留现场；不能删除可能属于其他会话的新锁。
- Orchestrator 只有在会话已终止、锁目录仍存在、读取到的 owner 不再活跃，并确认没有对应的 UE/UBT 残留进程时，才可以清理孤儿锁。活跃 Worker 的锁一律不代删。
- 构建、测试、编辑器连接或资产保存失败时，按项目规则报告错误并停止当前锁内阶段；不得捕获错误后返回成功，也不得改用占位资产、默认配置或替代流程。

## 排队与唤醒

Worker 进入排队时向 Orchestrator 提供：锁路径、自己看到的 owner 会话 ID（若可读）、已完成的锁外工作、需要的锁内操作和有限重试结果，然后挂起当前回合。Orchestrator 维护先到先服务的队列；持锁方报告释放或完成阶段后，Orchestrator 先确认锁目录已经移除且没有残留 UE/UBT 进程，再按队列顺序唤醒一个 Worker。被唤醒的 Worker 必须重新原子获取锁，不能假设之前观察到的空闲状态仍然有效。

如果持锁方异常终止，Orchestrator 按孤儿锁规则核验后再清理，并把清理结果和残留进程状态通知排队 Worker。不能在 Worker 仍运行时删除锁，也不能通过轮询争抢顺序。

## Orchestrator 派发清单

派发前确认：

- 实现指南已写明边界语义、失败行为和验收场景。
- 切片表包含每个 Worker 的独占文件范围、读取范围、验证夹具、依赖波次和锁需求。
- 公共文件由单一 Worker/波次负责，二进制资产写入集合零重叠。
- 需要跨模块连接的改动已安排前置骨架或收口桥接。
- 锁路径、owner 格式、重试上限、排队方式和唤醒责任已写入指南，而不是只放在派发消息里。

收口前确认：

- 每个 Worker 的锁外验证已经完成，且未越过文件边界。
- 锁内构建、无头测试、编辑器/MCP 操作按队列完成，日志能区分失败与成功。
- 持锁 Worker 已退出自己启动的进程并释放锁；工作区没有未说明的改动。
- 集成提交只包含指南允许的文件，未把其他 Worker 的资产或生成物带入。

## Worker 执行清单

1. 先读实现指南，核对基线、分支和工作区状态；发现边界或基线不一致先报告。
2. 在锁外完成阅读、代码编辑、脚本准备和可独立运行的验证；只修改自己的文件集合。
3. 需要 UE/UBT 宿主时按本技能申请锁，核验 `owner.txt`，冲突达到有限重试上限后排队并挂起。
4. 持锁期间完成构建、无头测试、编辑器/MCP 操作和必要的资产保存；不启用 Live Coding。
5. 在清理路径中确认自己启动的进程退出、核验 owner 仍归自己、释放锁，并报告构建/测试结果。
6. 按项目规则提交聚焦 commit；不推送、不创建额外 PR，除非用户或项目流程明确授权。

## 失败处理与禁止事项

缺少 `owner.txt`、锁目录状态不确定、公共文件归属不明、资产映射不完整、验证夹具不可独立运行、编辑器/MCP 连接失败或进程无法退出时，必须报告具体对象和原因并停止受影响阶段。不得静默过滤对象、自动修正路径或数值、换用默认资源、吞掉异常、强删锁、覆盖他人改动或以“看似成功”的结果继续。

本技能不要求新增 C++ 类型、蓝图逻辑或项目配置；具体实现仍由项目指南决定。任何项目专属路径、模块名、类名、地图名和资产名都应留在项目自己的实现指南中，不应复制到本技能或其参考模板。
