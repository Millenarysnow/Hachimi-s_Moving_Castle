# 建筑定义与模型

本文说明建筑身份、等级模型和卡片预览共用的数据边界。放置后的表现时序见 [建筑合并与局部变化](Animation/技术文档-建筑合并与局部变化.md)，功能碰撞边界见 [建筑功能分支](Animation/技术文档-建筑功能分支.md)。

## 目标与核心方案

**一种建筑由一份 `UCastleBuildingDefinition` 标识，每个等级直接生成一个建筑 Actor。** 购买、背包、放置、合成、回收和预览都沿用同一份定义，避免各入口分别维护类型、逻辑类和模型的对应关系。

**蓝图只承载等级模型和默认配置，规则由 C++ 决定。** 模型的独立 `UStaticMeshComponent` 保留在建筑自身，既供直接显示，也供零件动画使用；不再生成第二个模型载体 Actor。

## 结构与依赖边界

- **`FCastleBuildingDescriptor` 是可流转的卡牌描述。** 它携带定义引用以及本张卡的等级、颜色和数字，不能按模型名或建筑类别重新推断身份，否则回收与再次放置会变成另一种建筑。
- **棋盘的 `BuildingDefinitions` 是可用建筑池。** 开局卡组和商店读取这个池；等级类由定义解析，不能在商店另建一份类列表，否则购买与放置会使用不同配置。经济规则见 [经济与房间商店](技术文档-经济与房间商店.md)。
- **`ACastleBoard` 决定占用和生成位置，`ACastleBuildingBase` 决定建筑初始化与模型表现。** 定义实现位于 `Source/Moving_Castle/Castle/Data/`，建筑与棋盘位于 `Castle/Actors/`，预览位于 `Castle/UI/`。

## 定义校验与身份

**等级必须从一级连续配置，生成类的类别和等级必须与定义一致。** `ValidateConfiguration` 同时用于资产校验与运行时入口；缺失、重复、抽象类或错配等级都明确失败。不能用已有等级代替缺失等级，否则升级结果会与卡牌描述不符。

**每个实际生成的等级必须显式提供可见美术模型，缺模型直接失败。** 数据定义校验负责类型与等级；实例生成后，`ConfigureBuildingVisual` 检查实际组件，不再创建占位立方体。失败会给出具体类名及配置位置，棋盘销毁未提交实例、保留卡牌和原占用，卡片预览也返回同一错误。自动替代模型会掩盖蓝图层级或资源漏配，禁止恢复这一兜底。

**美术拆件位于 `VisualRoot -> BuildingMeshGroup`，功能地板位于 `GameplayRoot` 下。** 刀盾系列 27 个 FBX 按建筑族和等级保存在 `Model/Buildings/DaoDun/`，每次网格摆放保留独立 `UStaticMeshComponent`，分组保持恒等变换，不合批。功能网格即使可见，也不计入美术模型；美术仅参与 Visibility 选中，不阻挡导航。隐藏楼板按 500×500 cm 格面与 520 cm 中心距铺设，上层与底层相差 560 cm；功能碰撞忽略 Visibility，保留导航资格，防止屋檐和护栏污染行走面。

**四类功能建筑各自替换同名 `BuildingEffect`，每座建筑仍只有一个效果组件。** 箭塔负责持续发箭，炮塔负责弹药库与逐发伤害，农田负责账户入账和 NPC 增益，盾塔负责护盾激活与表现。运行状态归实例，等级蓝图不承担业务逻辑，具体机制见 [建筑效果触发](技术文档-建筑效果触发.md)。

**盾塔保留独立建筑身份及定义。** `ECastleBuildingType::ShieldTower` 位于枚举末尾，避免改变已有资产的类别数值；`ACastleShieldTowerBuilding` 与五个等级类共用 `DA_ShieldTower`，不能借用炮塔定义，否则购买、合成与回收会丢失身份。护盾球体与次数文字是原生功能子对象，位于 `GameplayRoot`，明确无碰撞、无导航并带 `MergeExclude` 标签；它们不能掩盖建筑美术漏配，也不能扩大卡片取景或卷入模型动画。

**箭塔和炮塔定义都必须配置有效的 `AttackData`。** 两者共享精确 1～5 级攻击数据校验与 Mass 追踪弹协议，但拥有独立攻击 DA 和投射物配置。炮塔每点数字的伤害倍率不能被误当成箭塔固定单发伤害，否则同一数据结构会产生不同入口的隐式解释。

**合成必须保持同一份 Data Asset 身份。** 同类别但不同定义的建筑不能合成；同定义建筑还需满足同等级、颜色、数字及占用形状要求。否则一个变体会被另一变体的模型和规则吞并。

## 定向放置匹配

**只检查玩家当前指向并高亮的一个面，颜色或数字相同即可。** 命中地面顶面时读取该地块属性，建筑放在本格；命中建筑面时读取该建筑属性，落点是该面的外侧邻格。其他邻居、未命中的地块以及建筑占用范围内的其他地面不能提供匹配，否则会出现高亮面完全不匹配却仍能建造的结果。

**匹配来源必须从射线解析一直保留到背包扣牌和最终生成。** `FCastleGridCursorTarget` 区分地面与建筑来源；来源失效明确拒绝，不能改用其下地面。`CanPlaceBuildingAtCursor` 同时驱动高亮颜色与点击校验，避免预览和真正建造各用一套规则。无方向的坐标接口固定使用正下方支撑面，不搜索其他邻格。

**空间规则按每个占用格分别判断。** 当前棋盘 XY 范围内，首层必须有地面，上层必须有正下方建筑或本卡自身的支撑格。范围外最多伸出两格，角上的斜向位置也允许，仍受八层高度和已有占用限制；外围格不要求地面或下方支撑，但整次放置必须来自一座已登记建筑的面，颜色或数字匹配规则不变。跨界多格卡不能让内部格获得外围的支撑豁免，也不能借地面顶面把部分格伸出棋盘。

**越界建筑仍可作为射线来源，超出距离的候选仍提供拒绝反馈。** 光标来源按占用登记判断，不能再要求来源格位于棋盘内；外侧邻格超过两格限制时仍解析高亮候选，由放置校验报告原因。最终占用登记也使用相同的距离和层高限制，否则会出现预览可放、点击失败的不一致。

**坐标入口不搜索其他邻格。** 首层外围没有地面，因此无光标的坐标入口不能在外围首层放置；上层仍可从正下方建筑的顶面匹配。普通房间与功能建筑共用这些规则。拒绝时保留原背包槽位和卡牌，成功后的飞入与合成沿用原流程。拆除不新增连通检查，移除来源建筑后已有越界建筑留在原地。范围扩张及隐藏地块的约束见 [棋盘范围与扩张](技术文档-棋盘范围与扩张.md)。

## 占用形状与模型坐标

**一级至四级固定占用 1、2、4、8 格，二级与三级允许垂直合成。** 二级是沿 X、Y 或 Z 紧贴的两格；三级是 XY、XZ 或 YZ 任一平面内填满的 2×2 方形；四级仍必须填满 2×2×2 立方体。合成使用两个同等级建筑的实际联合占用，不要求它们来自同一种拼法；两座垂直三级也能沿剩余轴组成四级。斜接、L 形、四格直线和不完整立方体均不升级。自动合成止于四级；普通房间仅一级且不合成。五级当前按单格描述和放置，奖励升级及其最终占用设计尚未接通，不能把四级自动合成直接扩展到五级。

**卡牌直接放置仍采用标准朝向，合成结果保留实际占用。** 二级卡沿 X 放两格，三级卡沿 XY 放四格；背包描述没有方向字段，回收后再放置也采用该标准朝向。自动合成不能重新生成标准放置形状，否则会把垂直占用转成水平占用，覆盖其他格子或丢失上层索引。

**四类功能塔各等级显式绑定本族同等级蓝图，二级和三级另配 `VerticalBuildingClass`。** `ResolveBuildingClassForDimensions` 根据实际占格选择水平或垂直类；两种类都必须继承本族同等级 C++ 类，缺失或错配直接拒绝。四类五级蓝图采用本族 LV4 美术拆件，但保留五级单格身份及单格功能楼板，不开放四升五自动合成，也不为模型大小更改占用。

**生成锚点是占用范围的底面中心。** `SpawnBuildingActor` 的 X/Y 取占用范围中点，Z 从最低格中心下降半个层高；偏移随棋盘旋转和缩放。把 Actor 放回格子中心会让按底部制作的模型浮起半层，移动组件补偿又会破坏作者变换。

**自动生成的主塔也使用同一底面中心规则。** 主塔虽然不是背包建筑，但棋盘中心格作为一个单格占用范围，生成位置同样从格中心沿棋盘局部 Z 下降半个层高；这样主塔与普通建筑的底面保持同一标高。

**正式模型不按占格尺寸或包围盒自动拉伸。** 格面边长 500 cm、间隙 20 cm，中心距 `CellSize = 520 cm`；层高 560 cm、首层中心基准高 262 cm，与刀盾系列层模块对齐。格面和光标按 500 cm 缩放，尺寸不一致直接拒绝生成地面；蓝图和关卡覆盖值必须同步，否则旧值会覆盖 C++ 默认配置。

**刀盾源文件按实际顶点轴导入，不能仅信任 FBX 的 UpAxis 元数据。** 这批文件的元数据标为 Y 向上，但顶点实际以 Z 表示高度；默认轴转换会把普通房间的 0～560 cm 高度转到 UE Y 轴。导入须显式保持 XYZ 轴、厘米单位与每个拆件，并核对底部 Z=0、层面 Z=560；不能旋转建筑 Actor 来掩盖导入错误，否则功能楼板与后续几何身份将使用不同坐标系。

**生成缩放与蓝图根缩放叠乘，旋转只适配平面朝向。** `MultiplyWithRoot` 保留作者比例；二级水平 X 使用 lv2、Y 使用 lv2 并绕 +Z 旋转 90°、Z 使用 lv2_vertical 不旋转。三级 XY 使用 lv3、XZ 使用 lv3_vertical、YZ 使用 lv3_vertical 并绕 +Z 旋转 90°。朝向作用于整个 Actor，不能侧翻或拉伸模型来代替专用垂直类。

**两个额外变体是独立 `ABuildingNavigationActor` 蓝图。** `BP_Variant_LV1` 保留断开护栏的 1 个网格，`BP_Variant_LV2` 保留带梯子楼板的 2 个网格，均由根下的 `BuildingMeshGroup` 整体变换。它们不参与运行时 PCG 自动替换；新增建筑或变体网格必须纳入五份定义共用的 `DA_BuildingPartCatalog`，避免同形零件在跨等级合并时失去几何身份证据。

**已有建筑蓝图必须原地更新组件，不能删除重建。** 定义等资产持有其引用，删除后重建同名对象会留下内存悬空引用并引发 GC 崩溃。Blueprint 子对象枚举可能同时返回组件 CDO 与 SCS Handle，删除旧叶节点须按变量名去重，排除原生和不可删除组件，单批删除后编译并重新枚举，避免同一 SCS 节点被删除两次。

## 卡片预览

**预览生成与场上相同的等级类，并复用同一初始化和尺寸来源。** `UCastleBuildingPreviewSubsystem` 读取当前棋盘尺寸后创建瞬态建筑，避免卡片另造一套模型规则。预览隐藏建筑标签和功能几何，美术组件仅供 SceneCapture 显示。

**同定义、同等级共享法线纹理，卡牌颜色在各自材质中应用。** 缓存不按颜色拆分，因为轮廓取决于几何；重复卡牌不应重复生成模型和捕获器。可见卡片才保持捕获更新，世界结束统一释放预览对象。

**捕获设置必须跨组件注册保留，法线纹理必须保留负分量。** `SetShowFlagSettings` 避免注册时重建 ShowFlags 丢失配置；浮点 RenderTarget 避免负法线被截断。只改临时 ShowFlags 或换成不保留负值的纹理，会丢失轮廓或出现天空、雾等背景。

**首次渲染资源未就绪是等待状态，缺失配置是错误。** 预览等待网格资源并有明确超时，不用另一种模型或静态图片掩盖失败；否则卡片与实际放置的建筑会不一致。

## 已否决的方案与扩展边界

- **不恢复独立模型 Actor、额外模型类或模型偏移字段。** 它们会让等级配置、预览与零件动画再次依赖两套对象，破坏直接生成等级建筑的统一入口。
- **不把拆件合成一个静态网格来简化管理。** 飞入和局部合并依赖各零件自身的几何与变换，合网格会丢失这一表现基础。
- **五级奖励升级和 PCG 房间结构仍需独立设计。** 四类效果已支持五级，但这不开放四升五自动合成，也不替美术模型生成缺失的行走楼层。新增等级或模型仍须守住定义身份、占用规则和底部锚点。
