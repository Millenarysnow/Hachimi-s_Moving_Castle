# UE 5.8 MCP 接入

本文记录项目使用官方编辑器 MCP 的职责边界与约束。它说明为什么这样接入，具体工具和参数以当前编辑器暴露的 schema 为准。

## 目标与核心方案

**MCP 是当前 Unreal Editor 的工具入口，不是独立的场景数据库或游戏逻辑层。** 项目启用 `ModelContextProtocol`、`EditorToolset` 和 `AllToolsets`，工具依赖目标编辑器实例及其已加载插件；项目配置存在并不代表编辑器已在线。

**能由 UE 原生 Python 接口完成的任务优先走原生接口，缺少能力时再使用 MCP。** 这是项目的工具选择约定；C++ 源码仍在工作区修改，蓝图只承载项目允许的配置与表现，不因有图表工具就迁移大量玩法逻辑。

## 结构与依赖边界

- **项目配置声明客户端连接，编辑器宿主决定实际能力。** `.codex/config.toml` 将 `unreal-mcp` 指向本机 `http://127.0.0.1:9876/mcp`；端口及启动偏好属于本机编辑器状态，不能当作可移植的游戏配置。
- **官方插件与工具集随发行版引擎提供。** 关键实现位于引擎 `Engine/Plugins/Experimental/ModelContextProtocol/` 与 `Engine/Plugins/Experimental/Toolsets/`；游戏运行模块不应依赖这些编辑器自动化工具，否则打包能力会被编辑器环境绑住。
- **场景、对象、资产和蓝图操作针对编辑器真实对象。** 工具返回的 UObject 引用在后续操作中原样使用，不能凭名称拼造 `refPath`，否则可能操作错误实例或失效对象。

## 能力发现与状态依据

**工具集合由当前宿主发现，不能把旧文档里的名称和参数当成固定 API。** `list_toolsets`、`describe_toolset` 与 `call_tool` 提供按需发现和派发边界；插件启用情况变化后，可用工具与 schema 也会变化。本文不复制工具目录，避免未来 agent 根据过期清单猜参数。

**连接成功必须由实际只读协议调用及目标状态共同证明。** 配置为 enabled 或 TCP 端口可达只说明连接前提，不能证明工具已访问目标项目；空关卡结果也不能当作已经加载目标地图。多编辑器环境必须以返回的项目和关卡状态区分实例。

**写操作必须依据本次读取的对象与属性。** 对象属性、图表结构和工具必填参数以发现结果为准；猜属性名、把任意空值填入必填字段或复用失效对象引用，会把协议成功误当成业务修改成功。

## 执行与保存约束

**针对同一编辑器的工具调用按结果串行推进。** 编辑器对象操作受游戏线程和当前状态约束，不能把依赖前一步状态的调用并行发出，否则读取结果、对象生命周期和修改顺序会交错。

**协议响应、任务完成和资产持久化是三种结果。** 异步工具可能只接收任务，修改也可能只让对象变脏；最终依据对应的状态查询与资产内容。把收到响应直接当成完成，会遗漏编译错误、测试失败或未保存修改。

**保存范围只能是本次明确修改的对象或资产。** 编辑器可能已有用户未保存内容，批量保存整个项目会夹带这些变化；dirty 状态只能帮助识别风险，不能扩大授权范围。运行与测试任务也不能在前一轮未完成时重叠启动。

**项目连接保持本机回环范围。** 当前接入没有设计远程身份认证与权限隔离；改成对外监听会扩大可修改编辑器对象的访问面。远程协作不能只改地址，需先定义独立连接与访问方案。

## 生命周期与扩展准入

**编辑器自动启动偏好不能作为共享配置的事实来源。** 官方设置属于 `EditorPerProjectUserSettings`，本机 Saved 状态会变化；新增 agent 或机器必须把宿主可用性当作运行前提，不能在长期设计中声称服务永远在线。

**自动化创建的无头编辑器必须由创建方收尾。** 遗留进程会占用项目和模块，干扰用户随后编译或启动；关闭范围仅限本次创建的实例，不能顺手结束用户正在使用的编辑器。

**工具服务仍是 Experimental 能力，扩展前以当前发行版实现和 schema 为准。** 本文不保证跨引擎版本工具名、返回结构或插件集合兼容；新增包装层需保留实际错误和结果校验，不能静默换用其他工具来冒充相同行为。
