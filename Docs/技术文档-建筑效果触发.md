# 建筑效果触发

本文定义所有可放置建筑接收触发的共同边界。NPC 如何产生进入事件见 [NPC 进入建筑触发](技术文档-NPC进入建筑触发.md)，建筑身份和占用形状见 [建筑定义与模型](技术文档-建筑定义与模型.md)。

## 目标与核心方案

**每个 `ACastleBuildingBase` 实例都拥有一个原生效果组件，并通过统一 C++ 接口触发它。** 建筑负责提供入口，组件负责效果状态和执行；NPC、后续建筑联动和主动调用共用入口，不能各自复制效果逻辑。道路也具备这套入口，但基础组件只记录触发，不凭空增加道路收益。

**本轮实现触发链和可观测反馈，不实现具体塔的攻击或经济结算。** `UCastleBuildingEffectComponent` 记录成功触发次数和最近上下文，提供原生扩展点与表现通知；箭塔持续射击、炮塔伤害、农田金币和连锁关系需要独立效果实现。独立主塔模型不属于可放置建筑族，其战斗组件继续使用既有体系。

## 结构与依赖边界

- **`ICastleBuildingTriggerInterface` 是外部调用边界。** 建筑基类的原生实现转发给自己的 `UCastleBuildingEffectComponent`；蓝图可配置和观察，不能用大量事件图替代 C++ 效果。
- **效果组件归单个建筑实例所有。** 共用定义资产不保存触发次数，合成产生的新实例拥有新的效果状态，否则同类建筑会相互污染计数。代码位于 `Source/Moving_Castle/Components/Building/Effects/`。
- **建筑区域登记与 Mass 桥接归 NPC 触发模块所有。** 效果组件不查找 NPC、不 Tick 扫描、不求解路线，详细设计见关联文档。

## 接收和执行约定

**入口没有冷却、忙碌锁或同帧合并。** 多名 NPC 同时进入必须分别接收，正在执行上一轮表现也不能吞掉下一轮逻辑触发。未来箭塔可以追加待射数量，但不能用“动画还没播完”否决一次进入。

**上下文区分 NPC 进入与主动调用。** NPC 来源使用带世界身份和 Mass 序列号的单位句柄，不要求 NPC Actor；主动调用无需伪造 NPC。后续连锁应携带独立上下文并显式定义递归规则，不能靠取消重复事件掩盖循环。

**接受、状态记录、原生效果和表现通知具有固定顺序。** 校验通过后先记录触发，再执行原生效果扩展点，最后发出表现通知。缺失组件、错误世界和无效来源属于错误，必须明确拒绝，不能临时创建组件或假定默认 NPC。

**接口及 UObject 效果只在游戏线程执行。** Mass 工作线程只生成值类型进入记录；效果如需改实体组成、生成或回收单位，必须遵守 Mass 的安全边界，不能在 Mass 正在处理时直接调用批量生成接口。

## 生命周期与反馈

**棋盘占用成功时登记区域，完成建造后才纳入 NPC 触发快照。** 飞入期间已有逻辑占用并不表示建筑可以接收效果；`SetPlacementComplete` 改变登记版本，最终快照只包含就绪实例。卡片预览和已注销的旧建筑不接收进入事件。合成按原建筑注销、新建筑登记处理，不能按格子数量复制效果组件。

**默认效果有明确的调试计数反馈。** 调试显示按实际建筑实例展示次数，正常运行关闭显示后不扫描建筑。表现可以合并绘制，但成功触发次数和原生效果调用不能合并。

**演示的场景计数文字直接读取效果组件。** `ACastleBuildingTriggerDemo` 只是可视化消费者，不自行增加计数，也不生成另一套进入事件；正式触发仍由同一 Mass 处理链产生。这样可见反馈与游戏逻辑保持同源。

## 扩展准入

**具体效果在原生组件扩展点实现，参数归配置、运行状态归实例。** 未来加入攻击、产出、常驻人员或连锁时，保留统一入口和每次触发语义；播放时长、没有攻击目标等情况如何处理待射数量，需要具体效果单独决定。

**当前触发计数不是存档身份或正式战斗统计。** 建筑回收再放置、合成替换和世界退出都会结束原实例状态。持久化或状态继承必须先定义规则，不能根据资产路径推断同一建筑。
