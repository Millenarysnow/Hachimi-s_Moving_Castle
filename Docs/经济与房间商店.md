# 经济与房间商店（逻辑测试版）

## 运行入口

使用发行版 UE 5.8 打开项目，在带有 `BP_CastleBoard` 的关卡点击运行。`BuildingDefinitionsTest` 提供可直接运行的验收场景。默认 GameMode 是 `CastleGameMode`，棋盘蓝图已引用四种建筑 Data Asset，具体配置见《建筑DataAsset配置》。

- 开局金币 100，沿用原有的 8 张测试卡牌和 10 格背包。
- 按 **B** 打开或关闭商店，也可以点击界面的关闭按钮。商店打开时显示鼠标，暂停玩家移动和视角输入，禁止向棋盘发送放置操作。
- 首次打开免费生成 6 张商品；关闭再打开保留同一批商品及售罄状态。
- 点击商品下方按钮购买，金币扣除后卡牌加入背包，对应槽位售罄。购买不会自动补货。
- 商店内也可以按 **1–6** 购买商品、**R** 刷新、**Shift+1–9、0** 出售对应背包槽位；键盘和鼠标使用完全相同的交易接口。
- 点击刷新花费 2 金币，重新生成全部 6 张商品。允许重复牌，刷新后也可能抽到之前出现过的牌。
- 出售区显示背包槽位、类型、颜色、数字、等级和收益，点击后出售对应卡牌。删除后其余背包卡牌按顺序前移。
- 关闭商店后，按 **1–9、0** 选择实际背包第 1–10 格，明亮卡片表示当前选中。屏幕中心对准符合颜色或数字匹配规则的地面/建筑面，点击左键放置。按键现在对应背包顺序，不再对应原来的四种样例类型。

## 模块边界

`CastlePlayerController` 持有两个独立组件：

| 模块 | 职责 | 对外入口 |
| --- | --- | --- |
| `UCastleEconomyComponent` | 保存本局金币，拒绝负数、透支和整数溢出 | `TryAddGold`、`TrySpendGold`、`CanAddGold`、`CanSpendGold`、`GetGold`、`OnGoldChanged` |
| `UCastleShopComponent` | 商品生成、刷新、买卖、容量检查、商店开关 | `InitializeShop`、`TryOpenShop`、`CloseShop`、`TryRefreshOffers`、`TryBuyOffer`、`TrySellBackpackItem`、`OnShopChanged` |
| `ICastleCardPricing` | 根据卡牌描述及买卖类型报价 | `TryCalculatePrice` |
| `UCastleSimpleCardPricing` | 当前测试定价实现 | 道路买价 2；功能牌买价 `5 + 数字 × 2 + (等级 − 1) × 10`；卖价为买价的一半向下取整 |
| `UCastleShopWidget` | 展示商品和交易结果，将操作交给商店 | 复用 `UCastleBuildingCardWidget`，按 Data Asset 和等级显示与放置系统相同的模型预览 |

价格在商品生成时保存，购买扣款使用同一份报价。出售时使用定价接口重新报价。无效定价配置或负数报价会明确失败，不改用其他算法。

经济组件默认余额为零，控制器 `BeginPlay` 通过收入接口发放测试金币。经济属于当前对局，不包含跨局存档或联网同步。

## 可调整配置

在 `CastlePlayerController` 的蓝图子类默认值中可以调整初始金币 `InitialGold`。其 `Shop` 组件可以调整：

- `PricingStrategyClass`：实现 `CastleCardPricing` 接口的 C++ 或蓝图 UObject 类。
- 商品池读取绑定棋盘的 `BuildingDefinitions`：默认道路、箭塔、炮塔、农田四份共享定义。商店只生成定义中的一级卡牌，不再维护另一份建筑类列表。
- `RandomSeed`：默认 `20261108`。同种子、同配置、相同刷新次数可复现商品。
- `RefreshCost`：默认 2，0 表示免费刷新，负数无效。
- `RoomLimit`：测试值 30，预留由未来主塔等级系统调整。合计场上占用格数及背包卡牌对应格数，二级/三级/四级合成卡分别按 2/4/8 格计入。

此时商品在四种类型中等概率有放回抽样。功能牌在五种颜色、数字 1–9 中等概率抽取；道路始终是灰色 0 号。没有加入等级成长、权重曲线、锁定、免费刷新次数等尚未设计的规则。

## 失败与一致性

金币不足、满包、达到房间总量上限、无效槽位或商品售罄时，界面显示中文失败原因，余额、背包和商品不变。刷新在整批新商品生成及报价成功后才扣费，生成失败时连随机流进度也保持不变。交易过程拒绝从余额通知中重入另一笔商店交易。

## 测试命令

运行时按键盘左上角的 **~** 打开控制台：

```text
CastleAddGold 100
CastleSpendGold 50
```

命令通过同一个经济接口执行，并在屏幕和日志中显示结果。负数或余额不足会明确拒绝。可先消费到零，再打开商店点击购买/刷新验证失败提示；也可以连续购买至背包满，确认第三次购买不扣金币、不消耗商品。

自动化测试组为 `MovingCastle.Logic`，包含已有地面/背包测试和新增经济、随机出牌、交易测试。项目测试报告输出到 `Saved/Automation/EconomyShop`。

2026-11-08 验证结果：发行版 UE 5.8.2、Win64 Development Editor 编译成功，7 项自动化测试全部通过，包括在独立测试 World 中完成购买、背包入库及真实建筑 Actor 放置。独立游戏窗口还验证了 B 键开关、购买、重复购买拒绝、满包拒绝、出售、刷新、购买牌选择，以及 1440×900 下商店和背包的实际显示。

波次系统接入时由控制器取得商店组件并触发打开即可；商店状态通知会统一切换界面及输入模式。当前仅提供 B 键测试触发，不引入敌人、NPC、战斗或 PCG。
