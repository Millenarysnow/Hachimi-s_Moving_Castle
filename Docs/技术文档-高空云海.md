# 高空云海

云海填在固定的城堡与远景地表之间。地表的高度、可见范围与航程设计见[高空航行地表](技术文档-高空航行地表.md)；本文只规定云的体积、航行与关卡接入。

## 目标与边界

**近处透出地貌，远处连成云海。** 正俯视时能透过稀薄的云和掠过的碎云认出海岸和山脊，斜看远处时更长的视线在云内累积更多消光。云团仍有亮峰、暗谷和柔软的边缘，但不围住镜头；前景城堡与玩法空间处于云顶之上。

**云海只参与背景渲染。** 不移动城堡、不修改玩家飞行范围、不添加云碰撞、玩法天气或穿云机制。云层距离较近，本身就会比共享同一世界航速的地表掠过得更快，不为这种视差伪造另一套航速。

## 核心方案

**在同一个体积层中积累厚云、薄雾和碎云的消光。** `M_AerialCloudscape` 复用原生追踪和大气合成。二维覆盖图只调制厚云团的分布，不能把低覆盖区域直接挖空。稀薄介质和不同高度的碎云都取样于同一个随航程滚动的三维场；近透远密由积分路径长短自然形成，不用镜头俯仰角或屏幕遮罩制造透明窗口。密度在云层上下沿和远处连续归零，不能硬切。

**只对云的散射着色，不染地表的透射光。** 消光保持无色；RGB 反照率由局部云顶和云肩估计的天空可见度在暖白云顶与淡紫蓝云谷间过渡。体积自阴影保留明暗，适度的多次散射给阴面补光。不靠自发光或全局后处理染云，也不向城堡额外投射云影或把运动云海写入实时天空捕获。

**形状数据离线制作，运行时只读纹理并更新位移。** 覆盖图与三维噪声数据都属于云海插件。两者在水平轴严格平铺；小尺度采样的频率必须与云的完整周期相容。保守密度仅把所有介质都归零的高度和距离范围标为空；以覆盖图跳过稀薄区会让大云隙的硬边重新出现。

## 结构与依赖边界

**`AerialCloudscape` 独立拥有云的材质、着色器和运行时驱动。** `AAerialCloudscape` 显式绑定同一关卡的 `AAerialTerrainBackdrop` 与 `AVolumetricCloud`。它只能读取地表的航程，不读取地貌图、地表材质 UV 或城堡状态。地表不知道云的存在；云不依赖关卡导演、玩法、角色或 `Volumetrics` 示例插件。

**关卡拥有天空配置和实际云层高度。** `MainMap` 复用原有的云组件，不新增第二个相互替换的原生体积云。材质在编辑器里可静态预览，游戏中给本世界的材料实例更新位移。引用、材质契约或航程不可用时，写明对象及原因并停止这套云海的运行，不寻找其他 Actor、启用旧云材质或自行推算另一份航程。

## 航程、追踪与画面稳定性

**地表提供双精度、未按地表周期回绕的世界 XY 航程。** 云海在地表 Tick 后读取航程，并按云的周期回绕；所有密度采样共享同一相位。直接复用已取余的地表 UV 或只让部分噪声滚动，会在地表接缝处跳变，或造成云的内部纹理滑动。镜头位置及朝向不改变航程；已有地表出场 UV 也不是云的航程起点。

**优先保住从上往下穿过短云层时的采样密度。** 太少的沿线采样可能把有厚度的密度压成单一亮面；提高屏幕追踪分辨率不能解决这个问题。云海的采样预算在绑定的云组件内配置。远距离淡出须早于追踪范围边缘；最终质量以城堡遮挡、斜视接地平线和实际滚动速度下的画面为准，不把诊断用的电影模式当作项目默认设置。

## 扩展边界

**不采用滚动平面或定制渲染通道。** 平面在本项目需要的上方与侧上方镜头中暴露厚度不足。只有在密度造型成立、原生追踪仍无法在目标帧时内满足实测画质时，才考虑定制渲染。若要同时有独立的头顶积云、允许长期停留在云中或专门表现云的风切变，需要各自定义新的表现边界，不通过添加第二个原生组件或移动玩法世界实现。
