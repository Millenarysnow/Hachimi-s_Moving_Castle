# 建筑语义 PCG

本文说明城堡三维格网的语义求解、按格空间归属、双通道提交及规则扩展架构。建筑身份与模型资产见 [建筑定义与模型](技术文档-建筑定义与模型.md)，主塔四侧起始面见 [主塔侧面放置](技术文档-主塔侧面放置.md)，局部变化动画见 [建筑合并与局部变化](Animation/技术文档-建筑合并与局部变化.md)，导航更新时序见 [NPC 导航](Navigation/技术文档-NPC导航.md)。

## 目标与非目标

**目标：** 棋盘提交占用后，通过可扩展的多阶段语义规则与确定性噪声接口求得整盘建筑结构，并把结果准确落到每栋建筑的玩法碰撞、双向梯链接和可视化网格上；同时为悬挑斜撑、条件屋顶改写、转角结构及噪声外观变体预留无侵入扩展能力。

**非目标：** PCG 不决定放置合法性、卡牌扣减、等级自动合成或回收拆解（归 `ACastleBoard`）；不维护第二套独立寻路路网（归 Recast 与 `UCastleNavigationSubsystem`）；也不在运行时按网格厘米尺寸或组件名猜测零件语义。

## 核心方案：三层单向语义场管线

**先由规则与噪声在纯数据层求完整盘“语义场”，再按空间格分发给各建筑装配，最后分通道 Diff 提交玩法与表现。** 这条单向管线让任意复杂度的多格规则都能与动画、碰撞解耦，也不会因视觉过渡错误阻断导航。

```text
ACastleBoard（仅发布占用与布局提交事件）
    ↓
[1] 语义求解层：FCastlePCGBoardQuery + 多阶段 UCastleBuildingPCGRule + ICastlePCGNoiseProvider
    → 产出只读棋盘语义场 FCastlePCGSemanticField（格体 / 四向侧面 / 上下层交界 / 附加挂载件）
    ↓
[2] 按格装配层：V4 装配器 + 隔离的非 V4 占位适配器
    → 为每栋建筑生成独立的 GameplayPlan 与 VisualPlan（各自计算稳定签名键）
    ↓
[3] 双通道执行层：UCastleBuildingPCGComponent + UBuildingMergeComponent
    → Gameplay 通道（碰撞 / NavLink）先于 Visual 通道（显隐 / 动态网格 / 过渡动画）独立 Diff 提交
```

## 结构与依赖边界

代码位于 `Source/Moving_Castle/Castle/PCG/` 及其 `HachimisV4/` 子目录，规则集资产为 `DA_CastlePCGRuleSet`。

- **棋盘不知道任何具体 PCG 规则。** `ACastleBoard` 只维护占用并广播 `OnLayoutCommitted`，`UCastleBuildingPCGSubsystem` 订阅该事件。违反后棋盘会与特定造型或规则强耦合，无法独立测试和替换规则集。
- **规则层只读写纯数据，严禁接触组件、动画或导航。** `UCastleBuildingPCGRule` 子类只能读取 `FCastlePCGBoardQuery` 与 `ICastlePCGNoiseProvider`，并向 `FCastlePCGSemanticField` 写入语义结论。违反后规则将依赖 Actor 状态与求值顺序，破坏幂等性与无世界单元测试能力。
- **装配层只消费语义场，严禁重复判定业务连通或自行选梯。** 功能塔墙面、普通房墙面与梯井装配都必须直接读取语义场的结论，不得再自行调用 `CanTraverse`、判断主塔双门或按字典序另选梯格。违反后规则资产与噪声开关会失效，同一格面可能出现视觉与碰撞口径分裂。
- **空间归属红线：落在哪一格空间内的组件，归占据该格的建筑 Actor 所有。** 任何跨格或跨层交界不得把属于上层格的楼板网格挂在下层 Actor 下。违反会产生三类连锁故障：孤立单格普通房压在梯井上变成 0 可见网格空壳导致动画失败、建造准星瞄准上层地板却落到下层格、巡逻放点射线命中与功能楼板所属 Actor 错层。
- **表现动画不得反向否决玩法连通与导航。** `Gameplay` 通道与 `Visual` 通道分离提交；动画启动失败必须报错并保留已就位的视觉终态，禁止回滚已提交的碰撞与 `NavLink`，更禁止连坐回滚棋盘上其他建筑。

## 语义场与四类空间域

语义场 `FCastlePCGSemanticField` 描述整座城堡在当前占用下的结构施工清单，由所有规则共同填写，再按格分发给对应 Actor。按空间职责划分为四类域，避免把不同维度的决策硬塞进单一开关：

| 空间域 | 索引键 | 归属 Actor | 表达的语义范围 |
| :--- | :--- | :--- | :--- |
| **格体（Cell）** | 格坐标 `Cell` | 占据 `Cell` 的建筑 | 本格屋顶状态（保留 / 隐藏 / 覆写套件）、底盘状态（实心 / 梯洞 / 合并铺板）、普通房样例归属与朝向 |
| **四向侧面（SideFace）** | `(Cell, ±X/±Y)` | 占据 `Cell` 的建筑 | 该格前后左右四面墙各自的连通态（闭墙 / 开门洞 / 贯通无墙 / 主塔门洞）与可选墙体样式标签 |
| **上下层交界（VerticalInterface）** | 下层格 `LowerCell` | 拆分为上下两栋 | `LowerCell` 与 `LowerCell + (0,0,1)` 之间的层界态（无 / 封闭板 / 梯井含套件、朝向与洞口）；下层领竖梯，上层领带洞楼板 |
| **附加挂载件（Attachment）** | `(OwnerCell, Anchor, SlotTag)` | 占据 `OwnerCell` 的建筑 | 不属于主体墙/屋顶/地板的附加结构或饰件（如悬挑底棱斜撑、转角柱、屋脊件），显式声明挂点、套件、选中与导航资格 |

## 多阶段规则管线、全盘查询与噪声

**规则按三个阶段顺序执行，后置规则可以消费前置语义场。** 在 `UCastlePCGRuleSetDataAsset` 中显式配置规则列表，不再在运行时暗中补规则；缺规则或非法配置直接报错拒绝。

1. **Stage 1 · 拓扑与基础连通（`Topology`）**：计算每格四向侧面的连通语义（`UCastlePCGPlanarRule`，统一处理同色/同号通行与塔侧模式首层主塔 `±X` 双门）以及每道层界的封闭/梯位语义（`UCastlePCGVerticalRule`，统一处理功能塔与普通房互达分量，并统一接入噪声择格）。
2. **Stage 2 · 结构派生与覆写（`Structure`）**：消费 Stage 1 结果，派生建筑形态、屋顶覆写与附加结构件。例如 `UCastlePCGRoomFormRule` 计算普通房底盘/双层木构样例及避让家具的梯井朝向；未来的悬挑斜撑规则、按围合或连通轮廓改写屋顶的规则均归此阶段。
3. **Stage 3 · 表现变体与细节（`Detail`）**：消费前两阶段结果与噪声，决定纯视觉款式变体与装饰挂件，不改变玩法连通。

**规则通过只读的 `FCastlePCGBoardQuery` 访问全盘拓扑。** 除六邻外，支持任意三维偏移 `(dx, dy, dz)` 查询（支撑悬挑斜撑所需的侧下支撑判定、26 邻转角判定）、露天状态（`IsSkyExposed`）、悬挑状态与悬挑深度（`IsOverhanging` / `GetOverhangDepth`）、主塔门位以及按层水平连通分量。

**噪声通过 `ICastlePCGNoiseProvider` 统一供给且严格确定性。** 采样只依赖棋盘种子、空间键（格坐标或由侧面/挂点/分量根派生的稳定坐标）与具名语义通道，与建筑遍历和放置顺序无关；返回值必须在 `[0, 1)` 内，非法实现或空通道直接拒绝本轮求值。开启梯位噪声时，功能塔与普通房层界一视同仁使用噪声择格，关闭时取坐标字典序首格。

## 空间归属、V4 装配与普通房语义

**V4 建筑从绑定资产 `UCastleHachimisV4Layout` 读取显式零件分组，不再按尺寸猜语义。** 正式七族（箭塔、炮塔、农田、盾塔、气球塔、蜂巢、普通房，含单格五级）均为 V4 资产；SCS 作者件通过 `CastleV4Part=` 索引一对一映射，动态件支持 Visibility 选中射线，导航仅消费 `GameplayRoot`。

**跨层梯井按导入期已有的零件分组拆归上下两栋建筑。** 同一道梯井使用下层建筑本族的 `UCastleV4LadderKit` 保证几何与材质无缝咬合，但落地时严格按空间归属拆分：
- `Group == "Ladder"`（竖梯本体与梯口压条）连同双向 `UCastleLadderLinkComponent` 归**下层建筑 Actor**。
- `Group == "UpperFloor"`（带洞楼板）连同四条围洞功能楼板 `CutDeck` 归**上层建筑 Actor**（上层隐藏自身原实心底盘，由 `UpperFloor` 接替）。
- 任一 `UCastleV4LadderKit` 若缺少 `Ladder` 或 `UpperFloor` 任一组，或出现未声明分组，均视为资产配置错误并报错拒绝。
- 二层 V4 塔从 `InternalHatch.Opening` 所在格继续向上接外梯时，规则依次检查四个正交朝向，选择让下端落脚点和登梯点避开内梯开口及其水平净空的朝向。四个朝向均冲突则报错拒绝。

**普通房保留单格独立一级 Actor 身份，外观由规则按格拆分装配。**
- 水平拼接口径保持清晰区分：**同色**普通房相邻合并底盘并去双包边，接触面为 `MergedOpen`（无墙打通）；**异色同号**普通房相邻保留带门洞的共享墙（`OpenDoor`），由坐标字典序较小侧持有墙体视觉与阻隔碰撞；**异色异号**相邻为 `Closed` 闭墙；裸 L1 底盘仅在与异色房或功能塔接壤时按语义面装配 `Room_L1_Bay`。
- 垂直梯组按“下层水平可通行普通房连通分量 × 上层水平可通行普通房连通分量”配对，每对只启用唯一梯格；上下皆为普通房时，梯井朝向在四个正交方向中挑选不与两层作者家具包围盒相交的方向，全部受阻则报错拒绝。

**非 V4 占位建筑走隔离适配器，不污染 V4 主干。** 当前仅无 `HachimisLayout` 的占位建筑（如 `BP_SpeedRoom_lv1`）与极简测试夹具走独立的 `LegacyAdapter`，提供水平功能桥/阻隔与 40.8 cm/0 cm 高度过渡斜面；常态全 V4 棋盘不实例化旧版 `BP_Variant_LV1/LV2` 模板 Actor，待全部正式建筑迁入 V4 后可整体移除该适配器。

## 全盘纯求解、双通道提交与失败边界

**每次布局变更执行全盘纯数据求解，再逐栋按双键 Diff 提交。** 棋盘规模在百格级，纯内存语义求解开销在亚毫秒内，彻底取消 6 邻局部剪枝，确保悬挑斜撑、跨格屋顶等任意半径的复杂规则都不会漏更新；未发生变化的建筑因签名键一致而跳过任何组件操作与动画。

- **双签名键独立触发**：每栋建筑分别计算 `GameplayKey`（禁用原楼板 + 功能盒 + `UCastleLadderLinkComponent`）与 `VisualKey`（隐藏原件 + 动态视觉件 + 附加挂载件）。修改屋顶样式或增减纯视觉斜撑只改变 `VisualKey`，**不触发 Recast 导航重建**；仅改变功能碰撞时则不打断正在播放的合并/变化动画。
- **先验证与提交 Gameplay，再提交 Visual**：
  1. 整盘规则求值、资源校验与动态 Recast 就绪检查全部通过前，不修改任何场景组件；校验失败时明确输出 `UE_LOG(Error)` 并保持上一稳定状态。
  2. 在 `FScopedCastleNavigationChange` 内统一提交 `GameplayKey` 变化的建筑（更新功能盒、切洞地板与 `NavLink`），失败时逆序回滚本轮 `Gameplay` 变更。
  3. 对 `VisualKey` 变化的建筑独立捕获旧视觉快照、切换显隐与动态网格并启动 `UBuildingMergeComponent::StartChange`。单栋建筑的过渡动画若启动失败，记录 `UE_LOG(Error)` 并保留其已正确就位的视觉组件，**不回滚已提交的 Gameplay 通道，也不中断其他建筑更新**。

## 反直觉的坑

- **把上层带洞楼板挂在下层 Actor 上会击穿多项不变量。** 孤立单格普通房压在功能塔上时会因自身原底盘全隐藏而剩下 0 个可见静态网格，触发 `UBuildingMergeComponent` 报错并导致准星与路径点落格错层。正确做法是按 `UpperFloor` / `Ladder` 分组将带洞楼板归上层、竖梯归下层。
- **把表现动画失败当成棋盘 PCG 事务回滚会永久毒化整盘。** 若一栋建筑因动画失败导致 `AppliedKey` 未推进，后续任何位置的建造重算都会再次命中该建筑并整盘回滚。必须将配置校验失败与动画启动失败分界，且不得让表现失败回滚玩法通道。
- **装配层绕过规则输出重算 `CanTraverse` 会架空规则集与噪声。** 规则算完的结果是唯一真相；V4 墙面和普通房梯位一旦各自重算，规则资产增删与噪声开关就会静默失效。
- **依赖 6 邻增量过滤会导致复杂规则静默陈旧。** 悬挑斜撑依赖侧下方斜邻，连片屋顶与普通房梯组依赖整个连通分量；只有全盘纯求解配逐栋 Diff 才能同时保证正确性与低开销。

## 被否决的方案

- **维持下层持有整套梯井并放宽 `BuildingMerge` 允许 0 网格过渡。** 否决：这只是掩盖空间归属错位，建造准星瞄准上层普通房地板仍会错判成下层格，且削弱了动画组件捕获缺模型资产的错误校验。
- **继续沿用 `Ceilings(uint8) + Faces(bool)` 二元目标结构。** 否决：无法表达屋顶套件覆写、斜撑等非墙非顶附着件，新规则只能继续往过程代码里打补丁。
- **每轮重建旧版 `BP_Variant_LV1/LV2` 模板并按毫米尺寸猜零件角色。** 否决：在全 V4 棋盘上制造无意义的临时 Actor 生命周期与 WorldContext 风险，且模型稍作尺寸微调即失配。

## 未实现的部分与扩展准入

**当前尚未实现的扩展规则：** 悬挑斜撑美术套件与规则、特定围合/连通条件下的屋顶改写规则、转角柱/雀替规则、噪声驱动的墙饰与屋顶小品变体。架构层面已在语义场（`Cell.RoofOverride`、`Attachments`）、三阶段管线与双通道提交中预留完整接口并经自动化验证。

**后续接入新复杂规则的准入条件：**
1. 新规则必须实现为独立的 `UCastleBuildingPCGRule` 子类，明确声明所属阶段（`Topology / Structure / Detail`），并显式登记到 `DA_CastlePCGRuleSet`；不得把条件写进 `ACastleBoard` 或装配器主干。
2. 新规则所需的新美术件（斜撑、替换屋顶、转角件等）必须以统一格基准锚点（格底中心或格面中心）做成独立 Kit 资产并通过 DataAsset 显式引用，禁止按节点名前缀或包围盒尺寸在运行时猜测。
3. 新挂件必须明确归属唯一 `OwnerCell` 并声明是否参与选中与导航碰撞；纯视觉挂件不得触发 `GameplayKey` 变更或 Recast 重建。
