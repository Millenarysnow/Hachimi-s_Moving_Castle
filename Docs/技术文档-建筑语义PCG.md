# 建筑语义 PCG

棋盘提交占用后，建筑根据真实格面改变墙、屋面、行走面和双向梯。相关生命周期见[建筑合并与局部变化](Animation/技术文档-建筑合并与局部变化.md)和[NPC 导航](Navigation/技术文档-NPC导航.md)。

## 结构与归属

**棋盘负责占用和布局事件，`Castle/PCG` 负责部件计划。** `UCastleBuildingPCGSubsystem` 在建筑完成飞入后读取占用和六邻属性，生成格面目标。`UCastleBuildingPCGComponent` 保存原件身份、显隐和动态组件，`GameplayRoot` 持有功能板、阻隔和梯 Link。表现件支持选中射线，导航仅消费功能分支。

**V4 槽位、变换和网格来自明确绑定的装配资产。** `UCastleHachimisV4Layout` 记录 FBX 节点、作者覆盖格、墙型和梯井。SCS 作者组件的 `CastleV4Part=` 索引对应装配表。动画临时副本可以继承索引标签，原件识别以 SCS 创建来源为界。正式盾塔的七种造型都绑定本族装配，包括占一格的五级。独立屋面与主体内的零件按节点、锚点和几何校对后共用同一套网格，避免主体和替换层同时绘制。

## 格面与层界

**颜色或数字相同的真实四邻可通行。** 功能塔两侧各按本族、本级、本面的 Bay 或 Edge 墙槽装配，墙和门柱的作用范围限定在对应格。异色异数的接触面为闭墙。邻居离场时恢复各面的作者显隐。盾塔与其他 V4 建筑的作者站立面统一高于格底 40.8 cm，同层直接相接。与非 V4 的零标高楼板连接时，功能斜面才跨越高度差。

**每对上下功能建筑只启用一个梯格。** 按坐标顺序或规则集配置的确定性噪声挑选。下层按真实重合区移走相关屋面和接缝件，并持有梯与 Link。上层按同一个接口坐标切换原功能地板，四条板面围出净梯井。其他重合格保有完整楼板。楼体自己的内梯继续登记。V4 在下时使用本族楼板梯，盾塔也遵循此约定。只有接入不同高度的非 V4 楼板时才调整梯的垂直尺度；横向锚点保持一致，避免梯身与井口错位。

## 普通房间

**每格的一级房间持有自己的造型、碰撞、原 Actor 和卡牌身份。** L1 是露天木底盘。L2H 与 L3H 贡献单层连续铺板和外缘，L2V、L3V 与 L4 提供双层框架、墙位、分区屋面和连接件。样例依据真实平面、上下占用和暴露边分配，横向样例会转到棋盘的实际轴。七格缺角、长条和错层也沿格面处理。独立选择、回收和再次放置继续使用各房自己的占用和描述。

**共享接口由坐标确定单一所有者。** 同色普通房相邻去掉内部双包边。异色同数保留带门洞的墙，异色异数保留闭墙。脊件由覆盖格共同决定，接口改变时重算相关房间。在每道层界，上下两层的水平互达分量共同标识一个梯组，组内使用坐标最小的可通行梯格。上下任一层断开即可形成独立梯组。依据真实占用剪除屋面，空格保持空置。

## 验证与发布边界

**先准备整轮计划，再切换原件显隐与碰撞。** 各栋旧件由 `CreateVisualSnapshot` 捕获，接续时保留零件运动位置。试装期间保留此前的组件和 Link 注册，整轮成功后释放退场组件，失败时恢复显隐、碰撞、Link 和目标键。稳定键来自有序格面及装配几何。相同目标保留原动态组件和动画状态。

**导航在布局和动画事务完成后统一刷新。** `UCastleLadderLinkComponent` 依据本族站立与梯身动作点登记双向连接。Recast 路线以实际走廊中的 Link 为攀爬依据。巡逻取点使用命中格所属楼层的作者站立面，顶板美术的归属可以在下层。把碰撞或美术组件的所有者直接当楼层，会让叠放建筑的取点错层。
