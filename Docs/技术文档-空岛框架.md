# 空岛框架

空岛框架管理战斗间的离塔访问。单局阶段和下一步节点由[导演系统](技术文档-导演系统.md)持有，房间与徽章的发放边界见[背包道具与徽章](技术文档-背包道具与徽章.md)。

## 职责与扩展

**空岛基座提供空间、到达锚点和离开传送门。** 原生类位于 `Castle/SkyIslands`。玩法子类在 `OnInitializeIsland` 中准备本岛交互和资源，只依赖上下文与基座能力，避免玩法类之间出现交叉依赖。

**正式空岛由 `DA_DirectorConfig` 统一登记。** `SkyIslandClasses` 将 `Rest`、`Shop`、`NPC`、`Gamble` 分别绑定到 `ACastleRestSkyIsland`、`ACastleShopSkyIsland`、`ACastlePinballNPCSkyIsland`、`ACastleGambleSkyIsland`。休息节点固定进入 `Rest`。对应映射缺失或类无效时，导演报错并保留编辑阶段和当前节点。

**空岛类型由必填的 `DA_SkyIslandWeights` 决定。** 奖励节点按 Shop、NPC、Gamble 的顺序使用 2:1:1 权重，种子来自单局种子、关号和节点序号。房间传送门按 Shop、NPC、Gamble、Rest 的顺序使用 2:1:1:1 权重，其种子使用成功访问次数代替节点序号。零权重类型不会抽中，缺失配置、负权重或全零分布会拒绝进入，保留本次访问机会。

**节点空岛各占一关，成功返塔才提交进度。** 房间传送门返塔后保留原关号与节点。 导演以[导演系统](技术文档-导演系统.md)的同一关号发布后续节点。非 Shipping 构建的 `CastleEnterSkyIsland` 在可操作的编辑阶段直接指定四类之一，使用正式配置和相同的进出岛事务，便于在没有空岛节点的关卡验证玩法。

**四类正式空岛以岛面中心为局部原点，水平跨度为 2400±20 厘米。** 项目内可重导入的 FBX 位于 `RawContent/SkyIslands`，`/Game/MovingCastle/Model/SkyIslands` 下的网格已换算为厘米，岛体使用单位缩放。导演同时生成岛体和交互组件，共用岛根的世界变换。传送门中心为岛内 (700, 0, 200) 厘米，离开门美术从岛体网格独立拆分后挂在 `DeparturePortal` 上，组件以可见性查询碰撞接收瞄准射线并关闭导航影响。岛体 `IslandArt` 保留原资产名并设为 `NoCollision`，不阻挡机台和台座的交互射线。

**需要以真实外形反馈悬停的空岛部件使用独立静态网格。** 四座岛的出口资产为 `SM_SkyIsland_Departure_Rest`、`SM_SkyIsland_Departure_Shop`、`SM_SkyIsland_Departure_Gamble` 与 `SM_SkyIsland_Departure_PinballNPC`。赌博岛的轮盘、老虎机和气球回收机使用 `SM_Gamble_Roulette`、`SM_Gamble_SlotMachine` 与 `SM_Gamble_BalloonRecycler`。弹珠机投币台使用 `SM_Pinball_Console`。来源材质槽与坐标映射保持一致，交互组件继续在原世界位置接收射线。

**拆分网格的简单碰撞只覆盖本机台的局部包围盒。** 新资产复制自整岛来源并继承岛体凸碰撞，因此拆分工具保存交互网格时清除复制来的球体、胶囊体和凸包，再写入该网格的局部边界盒，确保可见性射线命中目标机台。

**拆分后的静态网格走完整编辑器构建。** `split_sky_island_meshes.py` 用修改后的几何重建渲染数据和距离场。Fast Build 会把快速构建标记写入正式资产，重载时曾产生无效 Bounds，导致正式空岛的距离场矩阵转换失败。

**可变外观由玩法组件持有。** 休息台领取后整台变灰。赌博岛保留固定机台和原生查询体，轮盘色格数与旋转指针由赌博配置驱动。弹珠盘、投币台和门柱共用盘面坐标系，滑车、金币和六款招募棋子分别响应移动、旋转和招募状态。把这些部件烘进岛体会让已招募的棋子留在盘上。

**岛初始化通过后才传送玩家。** 导演保存入岛前 Pawn 变换和视角，隐藏建造面，清除当前节点。传送、初始化或建造面准备失败时应留在塔侧，避免玩家进入半初始化空间。空岛阶段保留飞行和视角。

## 交互和离开

**交互接口由实际准星命中的 Actor 或组件实现。** 物件验证当前控制器和岛屿上下文，明确返回原因。控制器统一在非模态状态读取配置键，默认 E。悬停扫描使用同一上下文调用纯查询 `CanHighlightInteract`，正式校验与提交由 `CanInteract` 和 `ExecuteInteract` 承担。货位高亮由售罄状态决定，余额在交易提交时校验；已领取台座和交易中的赌博机不高亮。传送门广播离开意图，导演在 Tick 里先准备下一批节点，再传回主塔、销毁岛并推进。将销毁延迟到交互已返回，可避免回调仍在访问被销毁的组件。

**共享奖励由导演接到既有账户和控件。** 空岛调用基座请求一次免费换批、打开待领房间或发放徽章。导演验证请求来源是当前空岛，库存和模态输入继续走原有入口。子类内各自维护玩法状态，避免重复建立商店、房间选择和徽章替换业务。

## 休息空岛

**三个实体台座分别记录本次访问的领取状态。** `ACastleRestSkyIsland` 用专属配置提供免费回血、金币和额外房间商店。回血由主塔生命组件计算实际恢复量并同步气球。满血也可以消耗本岛这次机会，方便玩家确认台座状态。

**房间商店台只授予本次访问的一批免费商品。** 导演在本岛维护换批状态，休息台只在打开成功后标记已领取。玩家关闭界面后，台座和常规商店键均拒绝重开。离岛清除临时商店状态并返回主塔编辑阶段，此时主塔普通商店按常驻规则可再次打开。

## 商店空岛

**实体货位从两类配置池按本岛种子抽样。** `ACastleShopSkyIsland` 保证至少一个房间组和一个徽章，其余台座按池条目抽取并优先展示不同商品。每次进岛生成三至四个商品，正式配置为四个台座。空池、失效引用和非法数量或价格由岛初始化拒绝，保证导演传送后看到完整货架。

**确定房间组和徽章在交互时结算。** 房间组先准备全部牌面，扣费后按背包规则写入建筑栏和临时栏。徽章满六枚时，子系统接受待替换项即完成交易。玩家在替换界面选槽或舍弃均保留购买结果。发放接口拒绝时退还金币并保留货位。

**万能卡直到确认才扣费。** `UCastlePendingRoomReward` 校验所选牌面后调用商店的授权钩子，按当前余额结算。入包成功后提交售罄，入包失败时由商店退款。取消仅关闭选择，金币和台座不变，同一商品保留待领奖励及已抽中的候选。升级等普通奖励沿用原有免费领取流程。

**房间组台展示与发牌配置分层。** `UCastleRoomGroupDataAsset` 必须显式配置白、蓝、紫、金、炫彩之一；商店在初始化时校验稀有度和 `DA_ShopSkyIsland` 的网格、五档材质引用。任一房间组漏配或档位越界都拒绝发放或初始化，因为没有有效档位时无法保证台座展示与所售商品一致。

**全部房间组共用包底轴心网格和母材质。** `/Game/MovingCastle/Model/Items/RoomPack/SM_RoomPack` 底面位于包体局部 Z=0，摆在距岛面约 101 厘米的台座顶面。材质实例只替换五档基础色和 ORM。网格缩放 14.5 倍，包高约 190.4 cm。导入后印字正面指向局部 +Y，左货位 Yaw=0°，右货位 Yaw=180°，使包装正面朝中央通道。

**售罄反馈只作用于当前货位。** 确定发牌或万能卡确认完成后，`SoldAmount` 从 0 切至 1，基础色去饱和并压暗，粗糙度提高、金属度降低，箔膜法线仍保留。网格和 `QueryOnly` 可见性碰撞继续生效，价格牌显示 `SOLD OUT`，重复准星命中继续返回已售罄提示。弹窗取消、金币不足和发牌失败都保留原稀有度材质与可购买状态。徽章货位使用美术展示架，售罄后该架各材质槽统一置灰。
