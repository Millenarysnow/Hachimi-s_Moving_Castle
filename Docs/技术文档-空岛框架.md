# 空岛框架

空岛框架管理战斗间的离塔访问。单局阶段和下一步节点由[导演系统](技术文档-导演系统.md)持有，房间与徽章的发放边界见[背包道具与徽章](技术文档-背包道具与徽章.md)。

## 职责与扩展

**空岛基座提供空间、到达锚点和离开传送门。** 原生类位于 `Castle/SkyIslands`。商店、NPC、赌博和休息分别有独立工厂槽位。后续玩法子类在 `OnInitializeIsland` 中配置本岛交互和资源，依赖上下文与基座能力，避免玩法类之间出现交叉依赖。

**导演独占进出和步数提交。** 奖励节点从商店、NPC 和赌博按确定性流选一种，休息节点对应休息类型。实际 Actor 类必须显式登记在导演配置中，缺失时保留编辑阶段和当前节点并报告类型。正式配置在玩法交付前留空，测试夹具仅显式用于验收。

**岛初始化通过后才传送玩家。** 导演保存入岛前 Pawn 变换和视角，隐藏建造面，清除当前节点。传送、初始化或建造面准备失败时应留在塔侧，避免玩家进入半初始化空间。空岛阶段保留飞行和视角。

## 交互和离开

**交互接口由实际准星命中的 Actor 或组件实现。** 物件验证当前控制器和岛屿上下文，明确返回原因。控制器统一在非模态状态读取配置键，默认 E。传送门广播离开意图，导演在 Tick 里先准备下一批节点，再传回主塔、销毁岛并推进。将销毁延迟到交互已返回，可避免回调仍在访问被销毁的组件。

**共享奖励由导演接到既有账户和控件。** 空岛调用基座请求一次免费换批、打开待领房间或发放徽章。导演验证请求来源是当前空岛，库存和模态输入继续走原有入口。子类内各自维护玩法状态，避免重复建立商店、房间选择和徽章替换业务。
