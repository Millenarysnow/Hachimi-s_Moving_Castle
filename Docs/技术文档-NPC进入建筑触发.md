# NPC 进入建筑触发

本文定义共享巡逻的 Mass NPC 如何每次进入建筑时触发一次效果。建筑接收边界见 [建筑效果触发](技术文档-建筑效果触发.md)，路线求解和移动见 [NPC 导航](Navigation/技术文档-NPC导航.md)。

## 目标与核心方案

**把建筑区域与共享路线的交点集中编译成进入距离，NPC 根据本帧实际走过的路线区间产生事件。** 所有 NPC 本来就共享贴地折线和累计距离，因此空间相交只需在路线或建筑登记变化时计算一次。正常帧不逐 NPC 扫描建筑，也不增加 Actor、碰撞体或寻路。

**进入以 NPC 导航位置点跨入建筑的逻辑占用区域为准。** 使用棋盘局部坐标和占用格体积，保留棋盘旋转、缩放和垂直层；美术包围盒、屋檐、模型偏移和表现 LOD 都不改变触发范围。当前所有建筑形状由占用格并集表达，不按每格单独触发。

## 结构与依赖边界

- **棋盘登记真实建筑及其占用区域。** 放置、注销、回收和合成更新同一个登记源；卡片预览与未登记的关卡展示建筑不自动成为触发目标。
- **`UCastleBuildingTriggerSubsystem` 管理实例身份、不可变路线触发快照与游戏线程派发。** 代码位于 `Source/Moving_Castle/Units/BuildingInteraction/`。登记标识仅在本世界有效，注销后不能指向新建筑。
- **巡逻移动只记录本轮真实移动区间。** 新的 Mass Fragment 保存移动开始距离、行进长度和路线版本，不保存 Actor 引用或每实体建筑列表。
- **`UCastleMassBuildingTriggerProcessor` 在巡逻移动后读取区间。** 工作线程按 Chunk 收集值事件，结束后在游戏线程调用建筑接口。不能在工作线程访问建筑 UObject，也不能每次触发重新查询 NavMesh。

## 路线编译与进入语义

**沿最终 `PatrolPoints` 折线与逻辑体积求连续相交区间。** 不能只给每个 20 cm 采样点标建筑，否则短区域和边界会被漏掉。单栋建筑的重叠、接触区间先合并，再生成进入点，因此合成后的多格区域内部移动不会反复触发。

**闭环首尾属于同一次停留时必须合并语义。** 路线坐标从末尾回到零并不等于出楼再进楼；整条路线都在同一栋楼内时，绕圈不会产生进入事件。路线在同栋楼内折返也遵守这个规则。

| 行为 | 触发结果 |
| --- | --- |
| 从外部走入 A 并停留 | A 一次，停留期间不重复 |
| A 内跨格、上楼或绕过路线零点 | 仍属同次停留，不增加 |
| 离开 A 后再次走入 A | 再触发一次 |
| A 与 B 紧邻且为不同实例 | 进入 B 时触发 B |
| 一帧走过 A、B，最终落在外部 | A、B 均触发，按该 NPC 行走顺序派发 |
| 一帧跨过整圈或多圈 | 保留经过的每次真实进入 |

**区间采用起点排除、终点包含，避免在边界停住后重复计数。** 体积使用下界包含、上界排除，减少共面楼层和相邻格的归属歧义；仅切线接触而没有走入区域不构成进入。

## 生成、重绑定和版本

**出生在楼内只建立当前位置，不补发“进入”。** 当前调试生成器沿整条路线均匀生成，若把出生当进入就会凭空触发整条路线。后续正式波次若需要出生触发，必须显式定义为另一种来源。

**路线重算、重新加入巡逻或建造替换本身不制造进入。** 先完成既有的位置重绑定，再记录这帧真正走出的距离；不能把旧距离与新距离相减，否则路线变化会被误当成高速穿楼。NPC 原地被新建筑包住也不补发事件。

**触发快照同时校验路线版本和登记版本。** 建造过程沿用既有失效暂停；稳定后再编译，不能让旧路线触发新建筑或让旧登记标识命中新实例。销毁和世界退出清理登记及事件，过期目标不产生效果。

**工作线程只读取快照，派发时再次核对实例有效性。** 同一 NPC 的进入事件保持路线顺序，不承诺不同 NPC 之间的并行采集顺序。无效 NPC、已注销目标和过期事件被拒绝，不能用旧槽位替代。

## 已否决的方案与扩展边界

- **不依赖 `BeginOverlap`。** 当前人形表示是骨骼实例，不为每个 NPC 创建碰撞 Actor；增加 Actor 会改变现有规模成本，并让离屏表现影响玩法。
- **不只比较两帧终点所在建筑。** 这种方式会漏掉一帧完整穿越、同帧出入和多圈行进。
- **不限制为“每圈每楼一次”。** 同一圈可能多次真正出入同楼，必须全部保留。
- **本轮只覆盖共享巡逻位移。** 普通直线命令、传送、自由移动和未来避让没有这份精确路线区间，需独立提供实际运动轨迹后接入；不能用起终点连线冒充经过楼梯的路径。
- **当前效果入口与事件数量同阶。** 预处理消除了重复空间查询，不能消除必须执行的真实效果次数；具体效果应批量处理昂贵工作，同时保留每次逻辑触发。
