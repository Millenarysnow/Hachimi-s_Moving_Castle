# 主塔侧面放置

## 目标与范围

**主塔四侧代替地面地块成为正式对局的初始放置来源。** MainMap 显式使用塔侧模式，不生成地面格。旧模式、资产和地面扩张继续保留，靠关卡配置切换；同一局不混用，也不会因主塔或侧格故障回退到地面。房间、卡牌、PCG 和导航的既有规则不因墙面而重写。

**塔身每侧一列，正式塔侧棋盘逐级开放 3、5、7、9 层。** 格位按房间层高对齐，棋盘在预览、放置和占用登记时共同使用当前开放层数。每次只显出新增的塔身段，并在旧塔身与塔尖之间追加侧格，已生成的侧格、颜色、数字和房间占用保持原样。导航体积从开局就覆盖九层，房间仍通过既有几何变更机制更新 NavMesh。

## 职责与约束

- **`Castle/Placement/` 管理主塔侧格的属性、显示与命中身份。** 每局采样一次种子，颜色和数字按塔面、层及独立通道采样，本局固定。侧格随主塔呈现，只参与准星的可见性查询，不成为 NPC 行走面或实体障碍。素材或索引配置无效时拒绝初始化，不把主塔的任意装饰件当成可摆放格。
- **`ACastleBoard` 是唯一房间占用来源。** 侧格身份由塔身格坐标与朝外的面共同确定；四个侧面不能串用颜色或数字。落点是选中面外侧紧邻的空格，主塔整列不得写入房间索引，包括多格直接放置和合成登记，否则会与塔身重叠。
- **房间继续用同一套三维坐标和底面锚点。** 只改变第一块房间的放置来源，不创建各侧独立的房间棋盘，不将模型侧翻。塔侧格不是房间，不能作为合成对象或效果触发对象；除首层主塔 ±X 双门与门外紧邻房间开启门洞通行外，其余塔面与房间之间保持闭墙，真实房间只按六向共享面形成邻接，塔角不会把斜接房间视为邻居。
- **预判与提交保留同一个来源面。** 射线只接受已登记侧格的正面，已有建筑等前景继续遮挡；占用、隐藏或失效后不借其他面匹配。无光标的坐标入口不猜塔面，塔侧首块从显式选中的格面开始。匹配规则见 [建筑定义与模型](技术文档-建筑定义与模型.md)。
- **导演只控制侧格的可见性和取格碰撞。** 隐藏期间扩层时，新侧格也沿用隐藏状态，避免奖励或战斗阶段出现可选建造面。回到编辑后恢复原属性，始终保留建筑索引与主塔表现。
- **塔身与气球吊挂按 560 cm 正式五级套件（`SM_MainTower_L01~L05` + `LiftKit`）分级呈现。** 主塔底座固定 `515 × 515 cm`、层距 `560 cm`，单局 Lv1～Lv4 依次切换对应的 `SM_MainTower_L01~L04` 整塔模型（3、5、7、9 层，`SM_MainTower_L05` 11 层导入预留）。塔身美术组件只保留 `ECC_Visibility` 射线查询与遮挡，统一关闭导航参与，避免闭合外墙截断首层 `±X` 双门通道；主塔内部行走面仅由一楼双门内侧的不可见功能地板提供。
- **拉索与大气球按作者 `lift_rig` 对位装配，并与底层血量数值解耦。** 五级塔身网格已在对应挂点烘焙固定挂环，独立的 `SM_LiftAnchor` 保留并校验，重复实例化会造成共面闪烁。`UCastleMainTowerBalloonComponent` 从烘焙挂环的吊耳起装配 `SM_LiftTether` 拉索与 `SM_LiftBalloon_*` 大气球（Lv1～Lv4 依次为 1、1、2、3 颗，预留 Lv5 为 5 颗），存活颗数按 `CurrentHealth / MaxHealth` 比例向上取整，归零时气球与拉索全隐。底层 `UCastleMainTowerComponent` 仍维持 5、10、20、40 的逻辑气球容量（基础每球 200 生命），保证二十心 HUD 与赌博空岛气球回收机的数值结算不变。

## 主塔生命与气球

**浮点生命是战斗与现有二十心 HUD 的数值来源。** `UCastleMainTowerComponent` 维护四级逻辑气球容量 5、10、20、40（基础生命默认按每球 200 点计算，升级设置新等级后补满生命），同时按当前生命占最大生命的比例驱动塔顶视觉吊挂套件的存活气球颗数（残血至少保留 1 颗，归零时全部隐去）。

**额外生命倍率按未加成的基础上限计算。** 徽章可按比例同步缩放当前生命，重复设置同一倍率不会叠乘。气球回收按基础每球生命扣减并先验证仍有存活气球，避免空岛交互触发主塔死亡。
