# NPC 弹珠机空岛

NPC 空岛采用策划案的方案三。玩家用金币发射弹珠，利用增殖门和反弹钉将弹珠送入巡游 NPC 的路径。NPC 吃满所需金币时立即加入本局待命池，玩家自行决定离岛时间。阶段、节点与返塔事务见[空岛框架](技术文档-空岛框架.md)。

## 场地与模拟

**场地以自身的斜面坐标作为判定基准。** 局部 X 向坡底，局部 Y 沿投币滑轨，局部 Z 垂直于地板。反弹钉、增殖门、NPC、金币和护栏都使用这个坐标。NPC 在地板平面横向往返，组件的 Up 轴沿地板法线，金币中心离地一个半径。移动与旋转整个空岛时，碰撞和显示继续使用同一个变换。

**金币运动以 120 Hz 固定步长推进。** `UCastlePinballNPCSimulationComponent` 沿斜面施加重力分量，求出每段位移最早的护栏、反弹钉、移动 NPC 或底端接触，再按行进顺序判断穿门。保留每帧不足一步的时间，固定相同输入和种子下的运动顺序。显示帧率变化时，门和 NPC 使用扫掠路径接受命中，避免薄门或目标落在两个离散位置之间。引擎的基础几何组件读取位置和滚动旋转，用于呈现场地和金币。

**同一枚金币对同一扇门最多提交一次增殖。** 门在配置数组里的序号是本场门 ID。首次穿越先记 ID，再增加 `乘数 - 1` 或配置的加数。子金币携带出生门的 ID，从下一步开始沿散射方向运动。这个次序保证子金币刚生成或金币反复经过门时，门内都不会递归增殖。达到默认 200 枚活跃金币上限时保留场上金币，并对受限的增殖记录 Warning。

## 投币与招募

**扣款和发射在同一游戏线程操作中提交。** `ACastlePinballNPCSkyIsland` 先检查发射范围、活跃金币上限和未招募目标，再通过 `UCastleEconomyComponent::TrySpendGold` 扣除一笔费用。余额不足时，账户与场上金币保持原状，面板给出拒绝原因。默认费用是 5 金。配置资产 `DA_PinballNPCSkyIsland` 定义费用、版面和招募阈值等独立参数，初始化前校验。版面参数越界会导致入岛初始化失败，避免玩家抵达一个无法正常操作的场地。

**招募发生在使计数达到阈值的那次碰撞。** 此时锁住该 NPC 的碰撞资格，向导演提交一次 `AddRunNPCCount(1)`。导演接受后，金币被消耗、NPC 从场地消失，已得人数更新到面板和本局待命池。已招募 NPC 再遇金币时不会参与判定。导演拒绝时模拟报错并退出操控，保留离岛入口。

## 操控与生命周期

**投币台使用空岛准星交互契约。** 操控期间，空岛持有一份输入组件和一份移动、观察忽略计数。退出操控或销毁空岛时，归还本岛持有的计数与输入，移除 HUD。输入由 C++ 处理，`UCastlePinballNPCStatusWidget` 通过 `BindWidget` 更新 `WBP_PinballNPCStatus` 内的文本，WBP 保留控件布局和样式。

**导演拥有离岛与保留奖励的边界。** 成功返塔时导演销毁当前岛，岛清理剩余金币、NPC 与模拟状态。招募结果已在命中帧写入导演，下一场战斗使用该单局人数。正式空岛由导演配置登记，弹珠机配置只负责本岛场内参数。

**独立验收访问复用场内逻辑和本局账户。** 单机 PIE 的验收入口在本岛持有入岛变换、视角和独立交互输入层，使用相同的投币台、传送门和招募接口。传送门请求延迟到输入调用结束后才返回并销毁空岛，避免仍在使用交互组件时卸载。验收访问保留导演的编辑阶段和关数。正式访问由导演接管，统一的调试入口与正式配置登记随空岛合入处理。
