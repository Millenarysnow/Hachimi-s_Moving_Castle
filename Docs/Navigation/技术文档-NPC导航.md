# 技术文档 - NPC 导航

本文记录已经敲定的设计结论、理由和边界，供没有会话上下文的 agent 直接接手。接口参数、关卡配置和验收操作见 [NPC 共享导航](NPC共享导航.md)；具体实现以源码为准，不在本文展开。

## 核心方案

玩家按顺序放置路径点，系统一次算完 **1→2→…→N→1 的完整循环路线**，再将同一份结果提供给所有 Mass NPC。基本分工是：**集中寻路、完整发布、共享路径、各自保存进度。**

后续开发应遵守以下结论：

- **不能只算当前路段。** 一批请求必须包含全部相邻路段和闭合段；NPC 到点、转弯和绕圈都不再触发寻路。计算量与 NPC 数量和行走圈数无关。
- **玩家顺序不可擅自调整。** 每对相邻点使用 UE NavMesh 的最小代价路径；默认区域代价相同，因此表现为最短距离路径。
- **整条路线共同成功或失败。** 任一点无法投影、任一段不可达或遇到不支持的特殊连接，都使本次结果整体无效并报告原因。禁止发布半条路线，也禁止用直线穿障碍等静默回退冒充成功。
- **只使用 UE Recast NavMesh。** 导航来源是建筑最终实际功能碰撞，不再建立建筑连通图或第二套路网。
- **逻辑留在 C++ 与 Mass。** NPC 不各自持有路径、AIController 或寻路任务；蓝图和关卡只承担配置与交互。

当前每个 Game/PIE 世界只有一条共享巡逻路线，使用默认导航 Agent。单个路径点表示原地待命；清空已发布路线表示停止巡逻。

## 路线生成与共享

玩家编辑的是草稿，连续放点、撤回和取消都不寻路；只有整组提交才替换当前请求，相同请求复用结果。已发布路线在草稿编辑期间继续工作。

集中求解不仅生成绕障碍的转折点，还沿选中的 NavMesh 走廊统一采样表面高度和累计距离。玩家路径点、导航转折点和表面采样是三个层次，不能混用。贴楼梯等高度数据同样只计算一份，所有 NPC 共享，而不是每个单位逐帧查询地面。

结果以不可变快照发布，重算时创建新快照，绝不原地修改旧数据，也不长期持有会随 NavMesh Tile 重建失效的引用。集中寻路和发布在游戏线程完成，Mass 工作线程只读快照与实体数据。

必须区分“玩家改了路线”和“原路线因导航网格变化而重算”：前者允许重新安排巡逻阶段，后者应尽量保留 NPC 原来的去返阶段。请求被接收不等于结果可用，消费前仍须确认快照有效且为完整闭环；持有旧快照也不代表旧路线仍然可通行。

## 建筑变化后的更新时序

已确定的顺序是：**几何开始变化 → 共享路线失效并暂停 NPC → 整轮几何变化结束 → 更新并等待 NavMesh 稳定 → 重算完整闭环 → 恢复巡逻。**

关键不是“再调用一次重建”，而是保证时序正确：

1. 路线必须在几何开始变化时失效，不能让 NPC 继续相信旧结果。
2. 建造、飞入、合并及取消/销毁要纳入同一套开始与结束配对；并发、嵌套和“飞入完成后立即合并”应合并为完整业务轮次，不能产生中间路线和重复计算。
3. 必须等引擎脏区与异步构建真正结束才发布；构建期间出现新变化时，旧结果应作废，不能晚到后覆盖新状态。

这套调度由导航子系统统一负责，采用事件驱动而非逐帧扫描建筑。新增会改变通路的功能必须接入同一生命周期；仅依赖引擎自行标记脏区，不能保证共享路线及时失效。

## NPC 跟随与进度保留

每个 NPC 只保存自己的路线距离、玩家路段、速度和圈数，按共享路线的累计距离采样位置。转向平滑只影响朝向，不能改变轨迹并切角穿墙；移动速度继续驱动现有 Mass 动画。

推荐沿完整路线均匀生成 NPC，并在生成时直接写入精确进度。**不能用空间最近点反推巡逻进度**：去程和返程可能重叠，同一位置对应不同阶段，最近点无法表达这种差异。

路线更新后的重绑规则也已确定：同一组路径点因 NavMesh 更新而重算时，只在原路段内重定位；玩家改变点列时才允许在整条新路线中定位。只允许附近重绑，偏离过远的 NPC 必须停止并提示，不能自动传送或另发接入寻路。

路线暂时失效时保留巡逻意图，等待有效结果恢复。显式直达移动、设置速度或停止命令会解除对应 NPC 的巡逻，普通移动逻辑也必须避开仍处于巡逻模式的单位，确保同一单位始终只有一套系统负责位移。

## 当前边界与扩展原则

当前只实现共享中心线上的循环行走。任意出生点接入、单位避让与编队、逐点驻留、多路线、多 Agent、存档和网络同步尚未实现；跳跃、门、传送等特殊 NavLink 动作目前明确拒绝。

扩展不得破坏“集中计算、完整发布、各自保存进度”的基础，也不能通过放宽失败检查或增加静默回退来伪装支持。局部避让可以扩展，但不应重新引入每个 NPC 独立计算整条巡逻路线的成本；若将集中求解异步化，必须识别并丢弃过时的导航或路线结果。
