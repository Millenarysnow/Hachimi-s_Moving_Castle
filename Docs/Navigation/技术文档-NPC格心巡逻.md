# NPC 格心巡逻

本文定义棋盘平面上的行走轨迹。共享路线的发布、NavMesh 更新、梯子和 Mass 跟随见 [NPC 导航](技术文档-NPC导航.md)；建筑效果以 [NPC 进入建筑触发](../技术文档-NPC进入建筑触发.md) 为准。

## 目标与边界

**格心是偏好，不是通行节点。** 空旷处，NPC 沿途经过各格中部；障碍挡住格心，只要原来的进、出方向在格内仍有连续通路，就在格内小幅绕行再接回出向中心线。格心投影失败不等于该格不可通行，也不意味着应从上一格提前改道。

**只改变棋盘上普通平面步行的轨迹。** 共享闭环与空投塔临时调动使用相同的平面求解。玩家点列及顺序、空投落点和接回点、梯子两端和攀爬轨迹仍是硬约束。无棋盘区域、非平面表面和梯子沿用各自的既有通行契约。普通 Mass 直移、战斗追击和逐 NPC 避让不在范围内。

## 通路与格内走法

**Recast 决定通路，棋盘只提供格距、坐标和走中偏好。** `UCastleNavigationSubsystem` 先求完整的原生路线，在玩家点和 NavLink 处划分普通行走段。平面段按棋盘坐标分出实质经过的格子；相邻格共用边界接驳点，可向通行面的中部移动，但不能改变格子访问顺序或跨越不存在的接缝。不维护第二套全城通路图。

**一个格子的入口和出口必须联合求解。** 例如 `(1,4) → (1,5) → (2,5)`，如果 `(1,5)` 的正中有 30 cm × 30 cm 的置物台，求解的是入口到出口的一条连续曲线；不能分别给进向、出向各选一侧，也不能因中心被挡而跳过 `(1,5)`。绕行以距离和偏离中心参考线为代价，在该格内搜索可行轨迹。若实际通路被截断，跨格改道由重建后的 Recast 决定；格内搜索无结果不等于证明整格阻断，应报出格坐标和原因，不发布原生折线冒充结果。

**实际转弯是经过验证的小圆弧。** 格内转向在前后线段上确定切点，留出空间后使用能放入的圆角。不能只把 Recast 障碍边上的尖角直接向内抹圆，那会切入 NavMesh 空洞。发布的是圆弧细分后的实际行走折线；检查每条弦连续可走且在同一平面，不仅检查样点能否投影。格边接驳、硬路径点和梯子不跨界平滑；有限候选搜索不能承诺任意形状下都有合法圆角。

## 几何和失败边界

**功能碰撞或显式导航修改才是障碍数据。** 置物台应通过 `GameplayRoot` 下的正式导航几何在楼板 NavMesh 上留下禁区。只放美术组件不会影响路线；运行时增删阻挡需要参与现有导航变化事务，使旧快照立即失效。以当前 Agent 的 NavMesh 作为净空判据，不对其边界重复加 Agent 半径，也不猜测美术包围盒。

**硬路径点不会因格心被挡而自动换位置。** 带有格心偏好的中间参考点并非玩家路径点。直接把被挡的格心选成玩家点时，这个精确落点仍应报不可用，不吸附到置物台侧边；也不能吸到相同 XY 的别层楼板上。

**所有消费者读取同一份最终折线。** 集中求解完成后统一生成 `PatrolPoints`、累计距离和梯子区间，Mass 和建筑触发各自不造一条近似轨迹。进入事件沿实际发布的线段连续求交，不按采样点触发。任何新的查询都在路线构建期完成，不随巡逻人数或圈数增长。

## 扩展边界

无需为单个家具登记专用占用格，更不能把中心失败变成二值封格。复杂或很窄的格内几何如果超出有限候选的覆盖范围，先补可验证的局部求解规则；不要放宽投影或跨到其他格子来掩盖失败。局部改线后的任意位置接入与人群避让仍需独立设计。
