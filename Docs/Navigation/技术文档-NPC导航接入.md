# NPC 导航接入

本文只记录玩家路径输入、关卡几何和外部玩法接入的边界。完整闭环、不可变快照、导航更新调度及巡逻进度统一以 [NPC 导航](技术文档-NPC导航.md) 为准，本文不重复其设计。

## 目标与核心方案

**输入层只管理玩家意图，导航子系统决定路线是否可用，Mass 层消费正式结果。** 草稿编辑、请求已接收和路线已就绪是三个不同状态，不能因界面出现路径点就认为 NPC 可以行走。

**当前世界只有一个正式路线请求和一个路径编辑所有者。** `ACastlePatrolRoute` 管理输入与反馈；`ACastlePlayerController` 协调城堡操作和测试生成入口；生成与单位生命周期归 `Units/Mass/`。输入实现位于 `Source/Moving_Castle/Units/Navigation/Interaction/`。

## 草稿与提交

**编辑使用独立草稿，放点和撤回不触发导航请求。** 进入编辑时复制当前请求的玩家点列；取消只退出草稿，正式路线继续运行。初始上限为两个玩家点，配置范围为 1–99，编号资产和草稿共用这一上界。超额放点时显示提示。提高上限只改变后续草稿的放点权限，保留既有路线。逐次放点就替换请求会让 NPC 为尚未完成的编辑不断停下和重算。

**整组提交通过 `SetWorldWaypoints` 进入导航子系统。** 接收成功后才更新 Actor 保存的局部点列，局部坐标只服务编辑摆放，求解请求使用世界坐标；不能把两种空间混用，否则旋转或移动路线 Actor 后落点会偏移。

**同步拒绝保留原请求；已接收请求随后求解失败则正式路线失效。** 空点列、相邻重合或导航配置错误可在提交入口失败，输入保留草稿供修正；不能把它们与投影失败、路段不可达等求解失败都描述成同一种“提交失败”。清空走独立清除入口，不能用空点列冒充合法路线。

**接收返回值不代表新路线可行走。** UI 应结合共享快照和 `LastFailure` 展示等待或错误；不能在导航尚在构建时直接生成普通直线路径，或用旧路线冒充新请求成功。

## 输入所有权与反馈

**编辑期间输入层先消费建造左键，退出后释放。** 编辑和建造不能处理同一次点击，否则放路径点时会同时放建筑。商店打开时禁止编辑并退出草稿模式，避免购买点击被巡逻输入截获。

**导演运行时只有编辑阶段允许巡逻草稿，开战明确取消草稿。** 门控由控制器查询导演；取消不提交、不清除已发布正式路线。奖励、战斗和结束阶段不能通过 P 或已打开的草稿绕过编辑锁；没有导演的测试地图保持旧行为，见 [导演系统](../技术文档-导演系统.md)。

**重复路线 Actor 停用并明确报错，不竞争全局请求。** 当前全局请求槽没有多路线仲裁；新增第二个编辑入口必须复用唯一所有者，不能各自持有看似独立的正式路线。

**路线所有者被主动销毁或流送移除时清除全局路线。** 否则界面入口消失后 NPC 仍沿无人管理的请求运行。状态文字只消费快照，不能反向触发求解。

**正式巡逻线独立于路点编辑，按世界开启。** `UCastlePatrolPathVisualizationSubsystem` 沿 Mass 实际消费的 `PatrolPoints` 绘制，复用 Path Tracer Toolkit 的 `Overview / PathTracer_08` 动态黄虚线材质与圆柱网格。虚线沿整条路线累计距离设置相位，因此各段的运动相位连续。只有已发布且含路段的有效巡逻轨迹才画线，失效即清旧线。显隐不改导航请求、地面圆圈或编号。只在开启时加载线条资产，替换资源时须维护 `PAL_CastlePatrolLine` 的打包依赖。

**重叠折返段用两条显示线，而不是两套虚线叠在同一根圆柱轴线上。** 反向滚动的遮罩重叠会让同一个缺口看起来只在原地开合，改动画速率不能解决。只在反向中心线相距不足一条线宽的位置把去程和返程向两侧分开，邻段接续；不改原材质、不丢弃返程，也不把显示偏移写回导航快照。

## 落点与关卡几何

**直接点击楼板，巡逻射线仅采纳建筑水平功能楼板与世界平地面。** `TryResolveWaypointFromRay` 对全对象多命中按距离排序，跳过外观组件、梯口压条、PCG 隐藏导航墙盒、非向上法线面及未处于站立标高的房内障碍顶面，只接受 `GameplayRoot` 下参与导航且阻挡 Pawn 的水平楼板与合法地面顶面，不再按屋顶外观反推室内地板。

**建筑功能楼板与跨层带洞楼板均归属对应楼层的建筑 Actor。** 命中水平功能楼板后核对已解锁楼层、占格登记与该层建筑的作者 `StandingHeight`（1 cm 容差），保留真实顶面标高并吸附到该格水平格心；高度恰好落于作者站立面但位于未解锁层、越界或未登记格的功能楼板明确报错拒绝。

**棋盘内的非建筑平地面取逻辑格心的 XY，保留实际顶面命中的 Z。** 有真实顶面才允许放点；侧挂模式没有地块 Actor 时仍能对齐逻辑格。棋盘外没有格子可对齐，沿用原命中位置。所有输入最终仍须通过原来的 NavMesh 投影；投影失败显示原因并保持路线失效，不扩大投影范围、不换用其他楼层或直线路径。

**棋盘外观不能作为落点可行走的证据。** 棋盘地块能被交互射线命中，但不会补出缺失的功能楼板；导航输入与精度约定以总方案为准，建筑资格见 [建筑功能分支](../Animation/技术文档-建筑功能分支.md)。扩大 Bounds 或投影范围不能修复缺失的实际行走面。

**地面圆圈和悬浮编号共同标出玩家路点，不参与取点或导航。** `ACastlePatrolRoute` 按当前草稿或已请求的点显示标记，玩家序号为 1～99。每个标记用 `MI_PT_Circle_Preview_04` 标出实际放点位置，编号仍用两面共享的一套数字网格。圆圈的渲染抬高不改变请求点或站立高度；圆圈与编号同属一个 Actor，撤回或清空时一起移除。所有展示网格必须禁用碰撞和导航影响，不能拦截下一次点选。

**项目默认值不覆盖关卡里已保存的 Recast 实例值。** 设计依据是 `Config/DefaultEngine.ini` 与关卡实际导航对象共同生效；只改默认配置仍可能保留旧精度。碰撞、净高、楼梯和 Bounds 必须匹配同一种 Agent，不能因组件已在功能分支就放宽可达性判断。

## 生成与外部变化接入

**巡逻生成器等待完整闭环后沿路线生成整批 NPC。** 等待依赖发布事件，不能为尚未就绪的请求先做普通网格生成，否则这些单位未必位于可接入路线附近。普通移动和巡逻模式互斥，单位底层边界见 [Mass 单位框架](../Mass/技术文档-Mass单位框架.md)。

**调试生成入口只拥有自己生成的批次。** 控制器替换其先前的巡逻生成器，不清空其他生成器；正式招募或波次需定义各自批次所有权，不能复用调试命令作为持久单位管理。

**主塔出兵会话使用主塔一楼内部的门内锚点作为路线首尾。** 塔底 +X 是门 A，−X 是门 B。`UCastleTowerDispatchDoors` 在主塔一楼内部门 A 与门 B 内侧各设一块不可见功能导航地板，外沿齐平主塔 ±X 格界以衔接门外房间，中央留出隔断空隙并向内收进 ±Y 边界，防止 A* 从主塔内部穿堂抄近路或与 ±Y 无门侧房间意外连通。导航重算时校验两处门外房间已就绪并对齐其站立标高，将两处门内锚点加入玩家点列两端；玩家可直接将首尾路径点放在门外紧邻房间而不发生重合，NPC 从门内走出迈入首间房时也会正常触发进入建筑效果。报错文案将首尾隐式点明确标识为“主塔门 A / B”，玩家草稿和编号只包含玩家点。

**出兵调度器只拥有自己生成的 Mass NPC。** NPC 在门 A 生成后才扣待命数，手动模式到达门 B 时由处理器标记，调度器确认实体销毁后才增加待命数。这样场上和池中不会同时计入同一名 NPC。自动模式到门 B 后在门 A 重置，继续消耗本帧的行走时间，不要求塔外返程。建筑进入事件沿实际走过的塔外路段计算，重置不会形成穿塔扫掠。快捷键与派出间隔由出兵配置资产决定。

**外部几何生产者在变化期间接入开始/结束配对。** 现有棋盘和动画已自行登记；仅有最终完成通知的外部生产者可请求一次刷新，但这不会抑制生成过程中的引擎更新。只改碰撞而不接入变化调度，会让正式路线继续引用过时空间；具体锁与发布顺序以导航总方案为准。

## 未实现的部分与扩展准入

**路线 Actor 的运行时变换跟随、多玩家编辑仲裁和路线存档没有接通。** 当前局部点列在提交时转成世界请求，移动 Actor 不会自动重新提交。增加这些能力前先确定请求所有权和提交时机，不能逐帧重复提交来掩盖状态归属问题。

**任意出生点接入、NavLink 动作和多路线扩展仍受总方案约束。** 输入或关卡层不能通过传送、直线兜底、增大投影范围来绕过尚未设计的行为，否则错误楼层和不可达路段会被错误接受。
