# 建筑功能分支

本文说明建筑功能几何与美术几何的统一边界。飞入、合并和预览分别见 [连续飞入装配](技术文档-连续飞入装配.md)、[建筑合并与局部变化](技术文档-建筑合并与局部变化.md) 和 [建筑定义与模型](../技术文档-建筑定义与模型.md)。

## 目标与核心方案

**功能几何按原生组件类型及附着层级识别，美术表现和导航共用这一边界。** `UBuildingGameplayRootComponent` 自身及任意深度后代属于功能分支，用于隐藏楼板、简化楼梯、碰撞盒和触发区域。它们必须随建筑移动，但不能随美术零件飞走。

**功能分支只表达职责归属，不自动生成或修正碰撞。** 是否可见、是否阻挡 Pawn、是否触发重叠以及是否影响导航，仍由各功能组件自身配置决定；把触发盒自动变成行走面会改变作者设计。

## 结构与依赖边界

- **`IsInGameplayHierarchy` 是统一的原生判断。** 实现在 `Source/Moving_Castle/Components/Building/`；从组件自身沿当前附着父链检查类型，中间可嵌套普通 Scene Component，不缓存旧层级。
- **`ACastleBuildingBase` 自带功能根，继承 `ABuildingNavigationActor` 的导航过滤。** 后者只定义建筑导航资格，不强塞棋盘、动画或建造状态；独立建筑模型也能使用这一边界。
- **普通 Actor 单独添加功能根只获得相关美术处理的排除能力。** 全 Actor 的导航过滤来自 `ABuildingNavigationActor`，不能把两个职责混为一谈，否则分支外的美术仍可能进入 NavMesh。

## 不变量与后果

**类型是身份，名称和标签不是身份。** 原生功能根重命名不影响识别；普通 Scene Component 改名为 GameplayRoot 不会获得功能。若改成按名称判断，模型整理或重命名就会悄悄改变导航与动画。

**所有美术处理先排除功能分支，参与标签不能覆盖它。** 飞入不隐藏、不移动、不生成其副本；合并不为其匹配零件或接管结果显隐。否则隐藏碰撞会成为飞行件，NPC 与触发区域也会随表现变化而失效。

**建筑初始化保留功能组件原有的碰撞、通道、重叠和导航开关。** 隐藏并不等于无碰撞；按可见性统一关闭碰撞会让刻意隐藏的功能楼板消失。

**功能几何不计入正式模型、标签高度或卡片取景。** 即使调试时临时可见，也不能扩大建筑的美术包围盒；专用预览只隐藏其显示，保留作者的碰撞与导航配置。否则卡片会缩到异常大小，只有功能楼板的建筑还会被误判为已有美术模型。

## 导航资格

**建筑只有功能分支可以参与导航，进入分支仍不保证生成 NavMesh。** `ABuildingNavigationActor::IsComponentRelevantForNavigation` 先确认组件属于当前 Actor、是场景组件且位于功能分支，再沿用引擎自身资格判断；有效碰撞、净空和 Agent 适配仍是必要条件。

**分支外的美术、标签、未附着组件及非场景导航修改器一律排除。** 此规则在组件注册和导航更新时生效，不依赖棋盘是否初始化；运行时新增或重新挂接组件也按当前层级判断。只在建造入口关闭美术导航会漏掉直接拖入关卡的建筑。

**功能碰撞不参与飞行，但路线仍等待整轮建造与动画完成后发布。** 功能几何已经存在和最终可用路线是不同状态；提前恢复路线会让 NPC 走进仍在替换的建筑。调度规则见 [NPC 导航](../Navigation/技术文档-NPC导航.md)。

**旧功能组件随旧建筑生命周期退出，结果使用自身功能组件。** 功能几何不经合并动画继承；由棋盘移除旧 Actor 后，它的碰撞也随之消失。若额外保留旧功能件，会出现重复楼板、残留碰撞和错误导航。

## 已否决的方案与扩展准入

- **不逐件复制排除标签，也不按可见性推断功能身份。** 深层嵌套、隐藏地板和重命名都会让这些规则失效；新增收集器必须复用原生层级判断，离线目录也不能混入功能网格。
- **组件移出功能分支后重新遵循普通美术规则。** 新增动态挂接逻辑必须同时处理碰撞与导航变化通知，不能继续沿用旧分类的缓存。
- **跨 Actor 的功能继承和自动碰撞生成尚未实现。** 若要支持 Child Actor 等结构，先明确各自所有权及生命周期，不能靠放宽当前 Actor 归属检查隐式扩展。
