# 操作模式与建筑拆除菜单

本文说明玩家双操作模式（经典 MC 模式 / 设计动物园之星模式）、语义输入解耦层以及建筑点击上下文拆除菜单的设计与约束。主界面左下角设置入口见 [主界面 HUD 与三态切换](技术文档-主界面HUD与三态切换.md)，3D 建筑卡牌表现见 [建筑卡牌表现](技术文档-建筑卡牌表现.md)，背包容量与回收规则见 [经济与房间商店](技术文档-经济与房间商店.md)，教程动态键位提示见 [对话与新手教程](技术文档-对话与新手教程.md)。

## 目标与非目标

**目标：** 支持玩家在「经典模式（MC 模式，默认）」与「设计模式（动物园之星模式）」两套完整操作逻辑之间即时切换，以语义输入动作隔离业务与物理按键；同时将场上建筑拆除升级为在点按位置弹出的上下文悬浮菜单（展示商店同款 3D 建筑卡牌 + 拆除回收按钮）。

**非目标：** 本期不制作任意单键自由重绑定的键位设置表 UI，不在战斗阶段开放建筑拆除，也不对拆除建筑做折算退金币逻辑（拆除统一退回建筑栏）。

## 核心方案

**在 `ACastlePlayerController` 与 `ACastleFlightPawn` 之上建立统一的语义输入与瞄准源抽象：业务层只响应“主放置/交互”“打开拆除菜单”“相机旋转门控”与“当前瞄准射线”，由操作模式决定物理鼠标按键映射、光标常驻态和射线起点。** 这样两套截然不同的鼠标心智可以共用同一套棋盘预览、主塔派兵、气球点破、路径编辑与拆除菜单，且未来扩展单键自由绑定时只需替换输入映射上下文（`UInputMappingContext`）而无需改动任何玩法代码。

## 结构与依赖边界

代码位于 `Source/Moving_Castle/Castle/Controllers/`、`Castle/Input/` 及 `Castle/UI/`，设置与拆除菜单资产位于 `Content/MovingCastle/UI/Common/`。

- **`ACastlePlayerController` 是光标显隐、鼠标捕获、瞄准射线与模态叠加的唯一仲裁者。** `ACastleHUD`（准星绘制）、`ACastlePatrolRoute`（路径放点）与 `ACastleFlightPawn`（视角转动）全部读取控制器的当前模式与射线接口，严禁各自假设“永远锁定屏幕中心”或硬编码 `EKeys::LeftMouseButton`。违反会导致设计模式下准星画在中心而点击落在鼠标处。
- **棋盘负责原子回收，菜单只展示回收牌并转发玩家选中的占格。** `ACastleBoard::DemolishBuildingCellToBackpack` 一并提交新布局和一张回收卡。直接销毁 Actor 或绕过库存容量检查会丢失房间或超出 10 格主栏上限。
- **拆除菜单复用 `UCastleShopCardWidget` 展示同定义、同色号的一级回收牌。** 卡片挂载后以独立宿主身份驱动 `UCastleCardPortraitSubsystem`，即使玩家从未开店也能成像。拖动卡片会在同一台 30 Hz 相机上请求倾斜视角，短点留在菜单内。

## 两套操作模式行为约定

| 维度 | 经典模式（MC 模式 · 默认） | 设计模式（动物园之星模式） |
| :--- | :--- | :--- |
| **常态鼠标与准星** | 隐藏系统鼠标并锁定视口，绘制中心十字准星 | 常驻显示系统鼠标且不锁定视口，隐藏中心十字准星 |
| **世界瞄准射线起点** | 固定视口正中心 `(Width/2, Height/2)` | 当前系统鼠标屏幕坐标 `(MouseX, MouseY)` |
| **相机视角旋转** | 移动鼠标直接旋转视角 | **仅按住鼠标中键期间**移动鼠标旋转视角 |
| **飞行移动** | `WASD` 水平飞行、`Space` 上升、`LeftCtrl` 下降；`Q/E` 不升降 | `WASD` 水平飞行、`Q` 下降、`E` 上升；`Space/LeftCtrl` 不升降 |
| **放置与世界交互键** | **鼠标右键**（放置房间、点击/长按主塔出兵、点破气球、路径编辑放点、空岛微缩盘放置） | **鼠标左键**（同左述全部放置与世界交互） |
| **空岛物件与房间传送门** | `E` 或配置的空岛交互键按中心准星交互；编辑阶段 `E` 可进入被准星直接命中的房间门 | **鼠标左键**按系统鼠标射线交互；`E` 只用于上升，不触发空岛物件或房间门 |
| **建筑拆除触发键** | **鼠标左键**点击已放置建筑弹出拆除菜单（空岛微缩盘撤回同用左键） | **鼠标右键**点击已放置建筑弹出拆除菜单（空岛微缩盘撤回同用右键） |
| **弹珠机瞄准态** | 鼠标右键 / 空格投币；`E / Tab / Esc` 退出 | 鼠标左键 / 空格投币；`Tab / Esc` 退出，`E` 不退出 |

- **设置入口与持久化。** 左下角齿轮与 `O` 键共用设置面板入口，面板内的「返回游戏」调用同一关闭逻辑，光标和输入焦点由控制器恢复。经典与设计两栏从语义映射读取键位说明，当前模式以金色选中画刷展示。选择预设立即生效，写入本地配置并广播变更事件，HUD 与教程据此刷新提示。设置和拆除面板都可用 `Esc` 或点击外部空白关闭。
- **经典模式通过按住左 Alt 临时操作 HUD。** 按住期间显示系统鼠标、暂停自由转视角并隐藏准星，玩家可以操作齿轮与其他 HUD 按钮。松开后恢复经典常态。如果已打开设置、商店或其他模态，模态继续持有鼠标和焦点，面板关闭后控制器按当前模式恢复输入。
- **建造栏卡牌可直接点击选中。** 设计模式可直接点击卡槽；经典模式按住左 Alt 显示系统鼠标后点击。卡槽点击由 HUD 消费，不会同时放置或拆除世界建筑，选牌状态仍由控制器持有。
- **设计模式将空岛与房间门交互统一路由到主点击。** 正式或验收空岛先检查微缩棋盘，再沿系统鼠标射线调用命中的 `ICastleSkyIslandInteractable`；空地未命中且导演校验通过时静默结束该次主点击，命中物件后的业务拒绝仍显示原因。编辑阶段先处理路径放点、气球、主塔派兵，再检查射线是否直接命中 `UCastleRoomTraitComponent`，命中门体即尝试传送并消费点击，屋顶、墙面与地面仍可放房。
- **经典交互键绑定必须显式不消费输入。** `ACastlePlayerController::BindSkyIslandInput` 以及验收岛输入绑定将 `bConsumeInput` 设为 `false`，因为控制器输入组件位于 Pawn 之前，消费 `E` 会阻止飞行 Pawn 收到设计模式的上升事件。绑定回调仍以控制器的当前模式门控，设计模式下不执行 `E` 交互。
- **模态覆盖优先级高于操作模式：** 商店、三选一奖励、升级领奖、徽章替换、图文弹窗、Galgame 对话及游戏结束界面打开时，统一由 `RefreshModalInput` 接管鼠标与视角忽略计数；关闭模态后精准恢复当前操作模式对应的常态光标与输入模式（经典模式回 `FInputModeGameOnly`，设计模式回不隐藏光标的 `FInputModeGameAndUI`）。

## 实时悬停白边

- **两种模式共用同一条可见性瞄准射线。** `ACastlePlayerController::TryGetAimWorldRay` 在经典模式读取视口中心，在设计模式读取系统鼠标位置。控制器每帧解析 `ECC_Visibility` 的首个命中，前景目标优先获得反馈，后方目标保留遮挡裁剪。
- **高亮目标服从当前玩法门控。** 编辑期的可用室内传送门只高亮门体，可拆除建筑高亮其可见外观；主塔只在出兵会话期间高亮，补给气球只在点击碰撞仍启用时高亮。活动空岛使用 `ICastleSkyIslandInteractable::CanHighlightInteract` 进行无副作用查询。商店余额不足时未售罄货位仍可高亮，已售罄货位和已领取台座不高亮。
- **模态界面、拆除菜单、左 Alt 临时 HUD 指针、巡逻路径编辑和弹珠机瞄准锁定期间清空白边。** 控制器在目标失效或视线移开时清除旧集合并恢复组件原始渲染状态。
- **路径编辑期间隐藏建造全息块并清空落点。** 控制器每帧读取 `ACastlePatrolRoute::IsEditing()`，退出后重新按建造条件解算射线。路径放点继续使用经典模式中心准星，避免建造预览与路径瞄准反馈重叠。
- **`UCastleHoverHighlightSubsystem` 只管理渲染标记。** 它为当前可见目标组件按位设置 CustomDepth，并恢复组件原先的 `bRenderCustomDepth` 与 Stencil 值。bit 0 保留给风格化渲染，bit 1 用作悬停位。材质通过世界级无界后处理体积绘制屏幕空间白色外轮廓，使用 CustomDepth 和 SceneDepth 裁掉遮挡像素。
- **交互状态查询必须保持纯读。** `CanHighlightInteract` 逐帧读取交易、领取和库存状态并返回布尔结果，交易提交与失败提示统一由 `ExecuteInteract` 处理。

## 建筑拆除上下文菜单机制

- **原位弹出与防裁切：** 在允许构筑编辑（`IsCastleEditingAllowed` 为真且非路径编辑态）时，用当前模式的拆除键命中已完成放置的 `ACastleBuildingBase`，立即在触发屏幕位置打开 `UCastleBuildingDemolishMenuWidget`（`WBP_BuildingDemolishMenu`）：
  - **设计模式**直接锚定在按下瞬间的鼠标屏幕坐标，并根据菜单尺寸与视口边界自动向内夹紧，防止靠近屏幕右/下边缘时按钮被裁切出界；
  - **经典模式**锚定在视口中心准星旁，并在菜单打开期间临时显出系统鼠标、暂停自由转视角，方便玩家直接移动少许距离点击「拆除」或点击空白处取消。
- **射线选中具体占格。** 棋盘把命中世界点反变换到棋盘局部空间，以格宽归一化 X/Y、以层高归一化 Z，再从命中建筑的占格中取最近格心。同距时按 X、Y、Z 字典序取首格，格宽与层高不等时仍能按格子深度选择。菜单保存建筑与占格，确认时重新校验两者归属。金边提示框仍直接位于 Canvas 槽，控制器需要该槽按实际菜单尺寸更新屏内位置。
- **成功时仅清空被瞄准的格子，返还一张同定义、同色同号的一级卡。** 剩余格优先提取三级四格方形（XY、XZ、YZ），再提取二级相邻对（X、Y、Z），其余各自为一级。每个形状以最小占格的字典序消解平局，保证同一拆除结果可复现。降级建筑直接落定并播放局部过渡，按最小格顺序检查可合成的外部已落定邻居。该路径绕开升级徽章赠牌，防止反复拆放刷卡。
- **拆除始终使用一次导航变更范围和一次布局广播。** 先准备所有替换 Actor，成功后才更换棋盘注册与背包。背包满或阶段拒绝时保留原建筑和库存，满栏提示玩家腾出空间，失效目标则关闭菜单。生成失败报错并保留原布局，提交后的动画错误单独记录。
- **主建筑栏与临时栏只存一级单格卡。** 背包各写入入口和背包放置入口对非法等级报错。拆除入口只接受一级至四级建筑，五级即使只占一格也报错拒绝。无目标格的回收接口只接受单格建筑，游戏内菜单始终携带具体格。按描述直接生成高阶建筑的接口继续用于棋盘与资产验证。
- **自动收起边界：** 点击菜单以外区域、对另一栋建筑再次触发拆除键（直接切换目标并重定位菜单）、按 `Esc`、按 `B` 打开商店、按 `P` 进入路径编辑或进入战斗阶段时，立即关闭拆除菜单并归还鼠标状态。

## 反直觉的坑

- **设计模式下使用 `FInputModeGameAndUI` 若未开启 `SetHideCursorDuringCapture(false)`，玩家每次左键放置或按住中键转视角都会导致系统光标闪烁消失或跳位。** 必须显式保留捕获期光标可见（或仅在中键拖拽期稳定读取鼠标轴增量）。
- **路径编辑态（`ACastlePatrolRoute`）与主塔长按连发出兵若仍写死 `LeftMouseButton`，切到经典模式后左键会同时触发拆除与放点/出兵冲突。** 所有世界主点击与按住检测必须统一查询控制器当前模式的“放置/交互键”。
- **设计模式空岛的空地点击必须在空岛分支内结束。** 若未命中微缩棋盘或交互接口后继续执行主棋盘放置门控，会把空地点击误报为阶段禁止构筑；空地射线静默返回，导演校验和命中物件后的业务拒绝仍保留提示。
- **瞄准输入层在设计模式也要保留 `bBlockInput`。** 弹珠机的高优先级瞄准层继续阻止 `E` 下传给飞行 Pawn，但专用 E 退出回调只在经典模式关闭瞄准；否则 E 会错误退出瞄准或在其下触发上升。
- **首次摄影同步完成材质或刷新渲染线程会冻结建造操作。** 建造预览与卡面摄影在 Tick 中轮询异步网格和材质，超过 30 秒报错。预览模型关闭阴影、动态间接光与光追参与，避免卡片占用关卡的光追资源。

## 被否决的方案

- **确认菜单保留一次用户确认。** 经典模式左键容易误触，确认前先展示这一格对应的回收牌。
- **多格塔的未拆占格留在棋盘。** 整座塔折成多张一级卡可能填满建筑栏，折成一张高阶卡则会把固定朝向的多格占用带入放置，导致重放时卡进主塔塔身。

## 未实现的部分与扩展准入

**未实现的部分：** 逐动作自定义键位表 UI、手柄映射及鼠标灵敏度滑条。

**扩展准入条件：** 后续接入完整自由改键时，直接在 `UCastleInputModeSettings` 的语义动作映射表上开放玩家覆写存档，业务侧严禁新增任何直接读取物理 `EKeys` 的分支。
