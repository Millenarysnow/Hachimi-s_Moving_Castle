# 建筑卡牌表现

本文约定建筑卡牌如何把色号、视差、真实建筑和闪卡箔光合成在同一张牌上。建筑身份和等级模型见[建筑定义与模型](技术文档-建筑定义与模型.md)，交易规则见[经济与房间商店](技术文档-经济与房间商店.md)。

## 目标与边界

- **第一眼读色号，第二眼看建筑。** 红、蓝、绿、黄、紫是本项目的玩法色；高对比的对角数字表达同色或同号匹配。名称、等级和交易信息各有位置，不用稀有度或箔光替代玩法色。
- **商店是首个接入面。** 新效果不改变出牌、买卖、价格、放置或合成。建造栏的小尺寸线框继续使用 `UCastleBuildingPreviewSubsystem`，避免把高清彩色捕获的成本扩散到战斗 HUD。
- **闪卡是表现，不是商品属性。** 当前用商店内的箔光预览对照同一组商品；不更换商品、不修改描述、不决定稀有度、不写存档。

## 核心方案

**卡窗内只有真实建筑是 3D 捕获。** 前后景是 UI 分层：远处的云和天空移动少、前景移动多，透明建筑图夹在中间。箔光独立贴在牌框和纹样上，色号和文字始终留在最上层。这样每张牌不需要单独布置一套 3D 场景，也不会把颜色、数字或文字烘死在建筑图里。

## 结构与职责

| 层 | 职责与边界 |
| --- | --- |
| `UCastleShopWidget` | 绑定商品及交易按钮，提供普通/箔光对照；不构造捕获场景。 |
| `UCastleShopCardWidget` | 消费只读建筑描述与捕获结果，处理悬停和牌面排版；不改商品，也不持有玩法状态。 |
| `UCastleCardPortraitSubsystem` | 复用正式建筑定义和棋盘尺寸，在隔离的摄影场景取景，负责静态缓存、当前卡捕获和资源释放；不读取交易状态、鼠标或箔光设置。 |
| `M_CastleCardFace` | 在同一个卡窗里合成远景、透明建筑、近景与局部箔光。材质不决定色号和建筑等级。 |

## 取景、透明与生命周期

- **取景基于真实等级模型，预览不运行玩法。** 不从关卡中截取已放置的演员，不拍棋盘、天空、标签或功能碰撞。独立灯光和镜头让牌面不会随着地图昼夜、主视口曝光或其他卡片变化。
- **建筑颜色与覆盖范围分开处理。** `SceneColor (HDR) in RGB, Inv Opacity in A` 给出线性颜色和反向不透明度。合成时使用 `1 - A` 作为覆盖率，不能拿 RGB 的亮暗扣黑底。若色彩已经乘过覆盖率，不能再乘一次，否则屋檐等细边会变暗；显示转换由牌面统一负责。
- **远近层次主要用美术分层，不给整个卡窗开相机景深。** 远景可画得软，近景可轻遮建筑，但 UI 层不会接收建筑的影子，也不参与 3D 遮挡。只有需要真实接触阴影的台座等几何，才随主体进入捕获；没有这项需求时使用建筑本身的底座。
- **静止卡只读缓存，任一时刻只有当前悬停卡请求动态视角。** 静止图不能被悬停目标覆盖，否则两张同名卡会一起转。离开、移除卡片或关闭商店即解绑悬停，彻底离开世界时释放摄影场景。首次入队是等待态；缺资产、初始化或捕获失败则明确报错，不拿旧图、其它模型或线框冒充。
- **共用的是画面，不是交互状态。** 目前色号、名称和箔面不改变拍到的几何、材质；同定义、等级和尺度共享静态图。若建筑材质将来按玩法色或数字变体，必须把实际影响渲染的值加入缓存键，不能让先渲染的图污染其它牌。

## 视差与箔光

- **同一倾角，三种响应。** 鼠标在卡片内产生局部倾角。远景和近景按各自深度偏移，建筑相机小幅绕行以露出真实侧面，箔光移动的是反射条带，不是印刷纹样。建筑画面不再作为一层插画做第二次 UV 位移，否则转动时会明显打滑。
- **可读牌面和交易区与视差解耦。** 近景、建筑和远景共享卡窗裁切；框和数字不随景物位移，交易按钮保持原点击区域。箔光只调制指定纹样，不能盖住对角数字或把红蓝等玩法色变成难以辨认的虹彩。
- **沿用分层思想，不依赖外部资源包。** `ParallaxCardMaterial` 的平面插画位移和效果遮罩可当参考；其 `_UI` 样例实际是 `Surface` 材质，也不拥有建筑的遮挡信息，直接套用会丢掉 UMG 输入和真 3D 的边界。

## 扩展准入

- **牌背与翻牌独立于建筑卡窗。** 公开版本使用原创「色号堡垒」图案；原版 UNO 标志和牌背不进入未经授权的资产。牌背、抽卡演出、背包接入和稀有度数据不属于首版。
- **增加透明或会发光的建筑特效前先验证 Alpha。** 玻璃、带后处理的发光和抗锯齿边缘可能具有不同的色彩与覆盖范围，不能假定所有 UE 捕获源的 A 都含有同一种数据。需要新通路时保持浅色与深色背景切换不出现暗边、方底或丢失镂空。
