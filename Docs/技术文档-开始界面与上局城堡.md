# 开始界面与上局城堡

游戏从独立的 `StartMenu` 地图进入。《哈基米的移动城堡》沿用《梦间》的皱纹纸原图、石墨色字标和模型自转节奏。前作的建筑线稿渲染属于《梦间》，续作保留塔身、吊挂和各色房间在战斗中的实际材质。

## 画面与入口

**左列固定承载标题和三行文字，右列固定承载立体城堡。** 标题使用本作名称，三个无边框入口依次为“新手教程”“开始游戏”“退出游戏”。它们分别进入 `TutorialMap`、进入 `MainMap`、退出游戏。只有选择入口才触发行动，鼠标悬停和键盘焦点都应可辨认。

**纸张固定在屏幕上，城堡每秒绕竖轴旋转 2°。** 这是《梦间》一圈三分钟的速度。相机按整座城堡转过一周所需的空间取景，窗口缩放时仍给两列分别留足空间。进入游戏的镜头与输入由目标地图自己的控制器接管。

**菜单使用专属 GameMode 和控制器。** 显示模型只需要可渲染的零件。主塔侧格、数字、房间标签、选中面、玩法碰撞、NPC 和战斗 HUD 均属于游局，在展示地图生成玩法棋盘会把这些状态一并带入菜单。

## 哪一座城堡

| 时机 | 下次进入菜单时的展示 |
| --- | --- |
| 首次启动，或只进过新手教程 | 正式开局的初始主塔和完整吊挂 |
| 正式局成功开局，尚未落成房间 | 这局的主塔 |
| 房间落成、合成、拆除，或塔身、可见气球发生变化 | 本局最近一次已提交的战斗外观，包括拆空后的单塔 |
| 中途退出、正常结算或重启程序 | 已落盘的最近一次正式局外观 |

**记录从正式局导演成功启动时开始。** 教程有自己的导演和固定发牌规则，练习摆放不会替换正式记录。新开一局会取代上一局。存档槽不存在才表示首次游玩，已有记录损坏、版本不符或资源失效时要明确报告原因，避免把数据问题显示成首次启动。

## 记录与重建

**持久化战斗美术终态。** 主塔由 `UCastleMainTowerBalloonComponent` 提供当前塔身和仍可见的拉索、气球。房间沿用 `UCastleBuildingPCGSubsystem` 整盘求解成功后的已落成建筑集合，记录作者零件和当前的动态连接件。删除最后一间房同样是有效提交，即使余下建筑的 PCG 签名没有变化。

**装配和合并期间使用目标零件的稳定可见性。** 飞入尚未提交的房间没有正式外观。合并过渡时，引擎临时隐藏目标零件并移动动画副本，直接扫描当前帧会记下半空零件或缺墙的房间。建筑展示使用目标网格、材质覆盖、属性色和相对主塔的变换，因此以后进入菜单也能看见上次实际生成的楼梯、屋顶和支撑。

**只在外观提交时更新本地存档。** 一轮房间重算完整成功后才替换记录。退出、重载和结算不依赖遍历正在销毁的 Actor，菜单也不恢复战斗、背包或随机数状态。首次展示和游局共用主塔套件的挂点与网格，避免主塔资源调整后出现两套造型。

菜单实现位于 `Source/Moving_Castle/Castle/MainMenu/`。房间美术和楼梯的规则见[建筑语义 PCG](技术文档-建筑语义PCG.md)，正式局与教学的职责见[导演系统](技术文档-导演系统.md)和[对话与新手教程](技术文档-对话与新手教程.md)。
